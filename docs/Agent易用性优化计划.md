# fsops Agent 易用性优化计划

> 编写日期：2026-11-10。
> 状态：P0、P1a 已完成（2026-11-10），证据见 `docs/Agent易用性评测基线.md`；P1b 未开始（缺模型/预算授权）。P2–P5 仍是计划，不代表已实现。
> 本轮范围：执行 P0（现状核对、契约盘点、基线冻结）与 P1a（确定性回归补缺）；未修改产品行为、未跑付费模型评测、未提交或发布。

## 1. 目标和基本原则

本轮优化的目标是：让 Agent 更容易选对调用方式，在失败后更快恢复，同时保持文件内容、编码、换行和并发保护的正确性。

优先级按以下顺序判断：

1. 不错误修改文件，不丢失其他进程的修改，不误报任务成功。
2. 提高完整任务成功率和错误恢复成功率。
3. 减少无效调用、依赖轮次和重复读取。
4. 在质量不退步的前提下，减少实际 token、总耗时和工具描述体积。

单次输出变短、工具数量少、工具执行快，都不能单独证明 Agent 更好用。所有收益必须说明适用场景、样本量、测量口径和局限。

以下路径均相对于仓库根目录。行号是编写时的定位参考，实施前应重新搜索符号。

| 项目 | 当前证据 | 后续处理 |

## 3. 范围与明确不做的内容

本计划覆盖：评测、工具描述、常用调用引导、错误恢复、截断与续读、相关兼容性和文档。

本计划不包含：新增工具、删除或重命名现有参数、默认改变写入保护、跨平台重写、全面接入 AST、扩展复杂 Office 编辑、自动修改宿主配置、改变权限或沙箱模型。

不把多文件逐文件原子写入描述为跨文件事务。不自动回滚已写文件，以免覆盖并发修改。不为了减少一次读取而建议盲目接受新 hash 或自动转换编码。

## 4. 阶段依赖与交付顺序

执行顺序：P0 盘点和基线 → P1 评测补齐 → P2 引导收敛 → P3 错误恢复 → P4 截断续读 → P5 综合验收。

P2、P3、P4 分别保留独立差异和评测记录，先逐项比较，再组合验证，避免同时改动后无法归因。

每个阶段完成后更新本计划的状态与证据；未通过阶段门槛时停止进入下个阶段，先修复或记录阻塞。用户后续如果仅授权某一阶段，到该阶段结束立即停止。

### P0：核对契约与冻结基线

目标：明确已有能力、真实缺口和测量方法。

任务：

1. 阅读 AGENTS.md、README.md、docs/工具参考.md、docs/轮次实测.md、scripts/check.ps1。
2. 检查 src/tools.rs、src/mcp.rs、src/adopt.rs、dsh/index.js 和生成脚本，追踪描述及引导流向。
3. 列出 fs_read 参数组合、互斥规则、默认预算、截断提示和错误恢复的实际行为。
4. 逐项映射已有单测、Windows e2e、DSH 冒烟和任务基准，标记已覆盖、缺失、待确认。
5. 记录 Git 提交、工作区差异、实际被测二进制版本与 hash；拒绝默默使用陈旧 release 二进制。
6. 运行现有确定性任务基准，保存原始统计；记录 schema 字节数，具备指定 tokenizer 时才另外统计 token。
7. 定义评测资源、模型配置、运行上限和数据保存方式。凭据不进入仓库。

交付：基线报告、契约与覆盖矩阵、评测运行说明。优先放在一份 docs 下的评测说明中，避免产生多份内容重叠的计划文件。

验收：每个优化建议都有证据或标为待验证；基线可复跑；实际二进制与记录对应；既有失败明确区分为环境问题或产品问题。

停止条件：存在未解释的错误写入、版本不一致或无法复现的基线时，不开始行为改动。

### P1：补齐确定性回归和真实 Agent 评测

目标：把工具正确性与模型使用效果分开测量。

#### P1a：确定性回归

扩展 tests/task_bench.py、已有模块单测及 tests/windows_semantics.py；只有现有结构无法表达时才新增辅助文件。

按第 5 节的任务矩阵补缺口。脚本可以安排固定调用链，但报告必须标明“确定性回归”，不能用它证明模型自然减少调用。

对每个场景校验最终内容、未授权文件未变、编码和换行符合预期、错误状态与磁盘一致。并发与部分写入优先用可控同步点或故障注入，避免依赖 sleep 碰运气。故障注入应限制在测试构建或测试接口，不进入默认生产行为。

#### P1b：真实 Agent 对照

采用两个独立对照，避免混淆问题：

- 产品效果对照：当前 fsops 与宿主原生工具；双方均可使用范围读取、搜索、精确编辑和合理并行。
- 改造效果对照：当前 fsops 与候选 fsops；同一阶段仅改变待验证项。

两侧使用相同模型版本、推理配置、任务书、fixture 字节和资源上限。每次运行使用独立目录和新会话，随机或交替运行顺序。fixture 的随机路径和运行顺序种子需记录；模型不支持 seed 时明确说明。

原生工具组必须禁用 fsops，并去掉“必须使用 fsops”的仓库及宿主引导；只保留双方相同的任务与内容安全约束。禁止把本仓库 AGENTS.md 的 fsops 路由要求直接带入原生工具组。记录两侧真实可见的工具描述和配置差异。

使用宿主调用日志记录参数、响应、错误、时间和 usage。Agent 自述调用数只作辅助，不能代替原始日志。固定脚本不得预先告诉真实 Agent 应使用的工具调用序列。

验收：确定性用例稳定通过；真实评测能恢复完整调用链；两个对照的结果分开呈现；缺失 token 数据标为不可获取。

### P2：收敛工具描述与常用调用路径

目标：降低首次调用失败和不必要的选择成本，保持参数兼容。

任务：

1. 将 fs_read 的常用路径放在描述开头：单文件 path；异构批量 reads；按模式 focus；末尾日志 tail。
2. paths、ranges、summary、block 继续支持，准确保留互斥关系、文件类型限制及大文件约束。
3. 根据 P0 结果区分服务端 instructions、逐工具描述、DSH 引导及宿主展示；先定位再去重。
4. 工具描述保留本工具必需约束，公共引导集中维护；宿主忽略 instructions 时也必须有足够说明可正确调用。
5. 保持 src/tools.rs 为真源；同步生成 DSH 定义和文档工具清单。
6. 先做“仅精简描述”对照，再决定是否补示例；本阶段不新增快捷参数或工具。

验收：公共说明字节量以减少约 25% 为实验目标，不作为硬性发布要求；参数误用和保护性约束遵循率不退步；既有合法调用兼容；MCP 与 DSH 均能完成代表任务。

停止条件：精简后 Agent 绕过精确编辑、忽略编码保护或不再能判断参数互斥，恢复对应说明并重新评估。

### P3：统一错误恢复语义

目标：让 Agent 从错误中知道文件状态和安全的下一步，避免盲重试。

先审计以下错误，保留已有有效恢复提示，仅修改证实存在的缺口：

| 错误 | 必须表达的事实 | 恢复要求 |
|---|---|---|
| E_NO_MATCH | 找不到的位置或范围；候选内容；本次磁盘状态 | 用实际内容修正目标，避免重复原参数 |
| E_AMBIGUOUS | 匹配数量和有限候选位置 | 增加上下文或限定范围；不得把 all=true 当默认答案 |
| E_STALE | 指纹失效、当前状态或当前 hash | 重新核对相关内容后决定是否仍可修改，不能只换 hash 放行 |
| E_LOCKED | 等待时长、本次是否写入 | 允许有上限的延后重试；持续占用时停止重试并报告 |
| E_MIXED_EOL | 混合换行事实、本次是否写入 | 说明显式归一的影响，不自动设置 normalize_eol |
| E_ENCODING_LOSS | 无法编码的字符、本次是否写入 | 修改内容或经明确决策转换编码，不自动转换 |
| E_BATCH / E_BATCH_PARTIAL | 预检失败或提交中途失败；已写、失败、未尝试范围 | 仅处理未完成项；已写文件如需再改必须重新核对 |

具体任务：

1. 区分单文件内存编辑中间态、单文件落盘状态、多文件提交状态。
2. 优先修改 stale_changed 提示的恢复顺序；设计“目标文本仍能匹配但外部语义已变”的任务，验证不会盲目重试。
3. 保留当前 batch_partial_error，核对真实失败分支及测试，而非仅验证格式化函数。
4. 对候选内容设预算，明确省略，不泄漏无关的大段文件内容。
5. 必要时复用小型恢复信息结构；避免为统一格式先重写整个错误系统。
6. 结构化 MCP 结果作为单独决策：只有宿主确实消费、CLI/DSH 映射清楚且重复输出成本可接受时才实施；否则保留文本契约。

验收：保护性错误不修改磁盘；部分提交报告与磁盘一致；模型不因提示自动放弃保护；适用的可恢复错误以一次修正继续为目标，需等待或重新决策的错误单独报告。

### P4：统一预算、截断和续读契约

目标：避免 Agent 把“不完整结果”理解为“没有更多结果”。

任务：

1. 盘点 read、grep、glob、inspect 的预算、limit、max_per_file、超时和长行截断语义。
2. 明确区分输出截断、条目上限、长行省略和扫描提前终止；count 的精确数与部分数不混用。
3. 续读提示使用真实返回的 next_offset 或 ranges，支持直接构造下一次合法调用。
4. 多文件读取逐项说明完整性；预算不足项不能伪装成空文件或成功读取。
5. 预算应覆盖标题、元信息、正文和尾注；预算小到无法表达有效结果时返回明确错误及建议，不输出破碎 JSON 或含糊半句。
6. 保留兼容性：优先扩展尾注，避免无必要地改变现有路径头、行号和错误码。
7. 说明分页期间文件集合变化的边界；offset 不是快照，不承诺在并发变化目录上无遗漏或无重复。

验收：静态 fixture 续读拼接后与预期全集一致，无遗漏或重复；串行和并行扫描结果保持既有契约；预算边界、UTF-8 中文边界和超大文件窗口均有针对性验证。

### P5：综合验收、文档和发布准备

任务：

1. 组合 P2～P4 的通过版本，重跑确定性回归与真实 Agent 留出任务。
2. 对照基线逐任务列出改善、持平、退步和原因；不只展示平均数或有利样例。
3. 更新 README.md、docs/工具参考.md、docs/使用指南.md、docs/轮次实测.md 中受影响内容。
4. 修正“省输出没意义”“每轮都固定重复计费”等绝对表述；区分上下文体积、实际 usage、缓存和账单成本。
5. 生成并核对 DSH 定义和文档清单；保留新旧参数兼容说明。
6. 按第 7 节执行检查，形成最终报告与回滚说明。

验收：确定性必测项全部通过；没有新增错误写入、误报成功或保护绕过；真实 Agent 数据达到第 6 节门槛。样本不足时标明初步结果，不宣传已证明的普遍提升。

## 5. 首批任务矩阵

以下任务优先利用现有 fixture 生成器扩展。参数边界用模块单测；完整链路用任务基准；模型选择和恢复用真实 Agent。

| 编号 | 任务 | 关键断言 |
|---|---|---|
| T01 | 陌生小仓库定位实现并回答问题 | 定位正确，答案可由源文件验证，无写入 |
| T02 | 大仓库按文件和符号缩小搜索范围 | 找到目标，不误把忽略目录内容纳入默认结果 |

| T05 | 修改一个函数内两处重复文本 | 只改授权范围，不误改同文件其他位置 |
| T06 | 三文件批量修改 | 所有目标正确，编码换行保持 |
| T07 | 重复匹配触发歧义后恢复 | 不默认全部替换，最终只改目标 |
| T08 | 目标不匹配后恢复 | 利用候选内容修正，不重复相同失败 |
| T09 | 外部修改造成 hash 陈旧 | 外部修改保留，重新核对目标适用性 |
| T10 | 锁短暂占用及持续占用 | 有限等待和重试，状态报告正确 |
| T11 | GBK / UTF-16 / BOM / CRLF 编辑 | 字节层验证编码和换行保持 |
| T12 | 不可编码字符与混合换行拒绝 | 磁盘不变，不自动转码或归一 |
| T13 | 批量预检失败及提交中途失败 | 前者均不变，后者完成清单与磁盘一致 |
| T14 | grep / glob 多页遍历 | 静态输入拼接完整，正确使用续页提示 |
| T15 | 长行及大于 32 MB 文件窗口续读 | 不把截断正文当完整内容，窗口路径不伪造全文 hash |

## 6. 测量口径和阶段门槛

### 指标定义

- 任务成功率：独立校验器检查内容、授权范围和任务答案，不采信模型自报成功。
- 错误修改率：发生未授权内容变更、外部修改丢失、错误编码写入或误报成功的运行占比；所有事件逐项展示。
- 无效调用：参数被拒绝、无新信息的重复查询或原参数重复失败；合理的保护性拒绝单列，不能全部算接口误用。
- 恢复调用：第一次错误返回后，到成功恢复所需的额外工具调用；无法恢复和不应继续的情形另列。
- 依赖轮次：必须等待前次返回才能继续的调用批次；并行发出 4 个独立工具调用算 4 次调用、1 个依赖批次。
- 耗时：同时记录工具执行耗时和任务总墙钟时间，不用前者替代用户等待时间。
- 字符与字节：参数、响应、schema 分开记录，不能直接换算成实际 token。
- token 与费用：宿主可提供时记录输入、缓存输入、输出 usage；不可提供时标为缺失。费用使用明确日期的价格计算，不用上下文长度猜账单。

### 运行规模

先使用 6 个代表任务、每组每任务 3 次独立运行排查评测问题；候选最终验收使用 16 个任务、每组每任务至少 5 次。按预算分批执行；正式规模是目标而非已授权的外部付费调用。

描述调优使用开发任务，另保留内容变体作最终验收；避免只围绕一套 fixture 改提示。报告原始样本数、成功/失败计数、中位数和分布；给出区间估计时说明方法，小样本不声称统计显著。

### 门槛

- 正确性硬门槛：确定性断言全过；无新增错误写入、丢失并发修改或保护绕过。
- 可用性门槛：候选与当前版本相比，参数误用、普通任务成功率和恢复成功率不能出现未解释的明显退步。
- 效率目标：被针对的任务，无效调用或恢复调用中位数减少至少 1 次；综合依赖轮次中位数尝试改善 10%。这些是实验目标，达不到时如实报告，不通过放松正确性换收益。
- 精简描述门槛：同时展示描述体积和任务质量；缩短本身不足以通过。
- 结果不明确时：保留兼容、低风险且有确定收益的修复；其余候选暂缓，不捏造“提升百分比”。

真实评测仅写隔离 fixture，任务结束清理本次创建的目录；日志按评测约定保存。原始日志可能包含本机路径和环境信息，入库前转为相对路径并剔除敏感数据；转换结果要与原始记录建立可追溯关联。

本计划不自动执行 git reset、删除用户目录、修改宿主配置、提交、push 或发布。后续实施应基于当时工作区状态，保留用户已有改动。
