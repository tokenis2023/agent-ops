# fsops v0.8.0

面向 AI Agent 的 Windows 文件操作层，MCP + CLI + DSH 插件三形态。

本版是一次**围绕「减少 Agent 轮次」的工具面重做**：token 就是钱，而每多一轮，
整个上下文（含约 6.2k token 的常驻工具 schema）都要重发一次。实测一次 `fs_grep`
输出仅 274–379 token、`fs_edit` 回执 58 token——**输出不是成本，轮次才是**。

## 一行安装

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/install.ps1')).TrimStart([char]0xFEFF)))"
```

## 本版改动

### 减少轮次

| 改动 | 省下的轮次 |
|---|---|
| `fs_write` 新增 `files` 批量（一次建/覆盖多个文件） | 建 N 个文件：N 轮 → **1 轮** |
| `fs_grep` 的 `matches`/`snippets` 首行带分布摘要 | 每处搜索：**2 轮**（不必先 files 再 count） |
| `fs_grep` 新增 `expand=block`（命中直接给完整代码块） | 每次「定位 + 读实现」：**1 轮** |
| `fs_grep` 默认 `limit` 100 → 200 | 每次翻页边界：**1 轮** |
| `fs_edit` 检测「半行 old」并给整行原文 | 每次踩坑返工：**3 轮** |

在真实 Agent 评测的任务流里（57 次调用完成一个文件密集型任务），这些合计让轮次
从 **57 降到约 39（−32%）**。

### 修复

- `fs_exec.env` 在 DSH 插件形态完全不可用（自由对象被投影成空封闭对象，宿主拒绝任何键）。
- DSH 插件：`fs_exec` 描述不再宣传 schema 已剔除的后台任务参数，传输层显式拒绝并提示改用 MCP 形态。
- DSH 插件：取消单个进行中的写/执行请求时会结束长驻会话，避免取消后继续写盘；长驻会话按 cwd 加 LRU 上限。
- `E_BAD_REGEX` 附 Rust regex 方言说明；`E_IS_DIR`/`E_BINARY` 补下一步；`fs_edit` 的 `E_READONLY` 与 `fs_write` 对齐给出 PowerShell 命令。

### 文档

- README/SECURITY/使用指南如实写清：DSH 插件是 Host 代码，Harness 的 fs 沙箱与审批**不覆盖** `fs_*`。
- 安装示例改为固定 tag/commit；补安装后自检、错误分层、`shell=true` 用法、从源码本地部署步骤。
- `package.json` 补 `engines.dsh` 兼容声明。

### 验证

- `cargo test --lib`：375 通过
- `scripts/check.ps1 full`：全绿（含真实 MCP e2e、任务级基准、版本一致性、DSH 插件冒烟 77 项）
- 工具 schema 总量 9,887 → 10,033 字符：新增两个能力只多 146 字符（嵌套描述去重抵消了大部分）
