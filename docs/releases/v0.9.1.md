# fsops v0.9.1

面向 AI Agent 的 Windows 文件操作层，MCP + CLI + DSH 插件三形态。

**补丁版**：v0.9.0 发布后合入的一组性能与文档修正。功能面与 0.9.0 相同（9 个工具），
**建议升级**——工具调用的 Rust 净耗时降了 2–3 倍。

## 本版改动

### 性能：工具净耗时降 2–3 倍

`call()` 每次都要做参数校验，而校验需要 schema——原先每次都重新构建 `tool_defs()`：
9 个工具、上百字段、约 10KB JSON 分配，单个调用光这一项就约 200µs，比实际读写文件还贵。
schema 是编译期常量，改为 `OnceLock` 进程内缓存。

长驻会话实测（中位）：

| 调用 | 优化前 | 优化后 | 提升 |
|---|---:|---:|---:|
| `fs_stat detail=server`（分发+校验） | 226µs | **41µs** | **5.5×** |
| `fs_stat meta` | 287µs | **93µs** | **3.1×** |
| `fs_read` 5 行 | 384µs | **191µs** | **2.0×** |

插件端到端（release 构建，Node 侧观测）：

| 场景 | 独立进程 | 长驻会话 |
|---|---:|---:|
| `fs_read` | 34.3ms | **0.31ms**（原 0.80） |
| `fs_stat` | 33.3ms | **0.12ms**（原 0.53） |
| 4 路并发一轮 | — | **0.23ms**（原 0.86） |

**分发+校验已降到与 `ping` 的 44µs IPC 地板持平**，这一层没有剩余空间。

### 两处刻意没优化的（附理由）

- **`fs_write` 约 3.5ms，其中 3.3ms 是 `sync_all()` 落盘**（`dry_run` 仅 182µs）。
  这是「临时文件 → fsync → 原子改名」防崩溃留半截文件的必要代价。端到端算账：
  40 轮任务写 5 次共 17.5ms，而 40 轮 LLM 往返是 40–120 秒，占比 0.02%。
- **`fs_read` 的 191µs 主要花在读全文做编码检测与 hash**。改成按行流式读能更快，
  但会牺牲编码识别准确性与 hash 一致性——那是功能换性能，不是纯优化。

### 文档与防漂移

- 修正 v0.9.0 遗留的过时说明：README / 使用指南 / 工具参考的工具数（8 → 9）、
  `package.json` 的 description 补上 `fs_inspect`、延迟宣称更新为实测值。
- **工具清单纳入生成**：新增 `scripts/gen_docs_tools.mjs`，README 工具表、各处「N 个工具」、
  `package.json` 工具清单全部从 `fsops schema` 生成；散文（每个工具一句话用途）
  放在 `TOOL_SUMMARY`，缺一个直接报错。
- CI 增加「文档工具清单与 Rust 真源一致」一步；`scripts/check.ps1 full` 增加两条防漂移守卫。
- 新增 [docs/轮次实测.md](https://github.com/tokenis2023/agent-ops/blob/master/docs/%E8%BD%AE%E6%AC%A1%E5%AE%9E%E6%B5%8B.md)：
  真实 Agent 的轮次对照数据 + 延迟逐层分解。

## 从 0.9.0 升级

插件与内核**必须同版本**（工具定义由 `fsops schema` 生成）。

- 用 install.ps1 或 `fsops upgrade` 升级二进制；
- DSH 插件把 pin 改为 `#v0.9.1` 后重装；
- 自检：`fs_stat detail=server` 应返回 `fsops 0.9.1 tools=9`。
