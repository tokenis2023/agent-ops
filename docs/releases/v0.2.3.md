# fsops v0.2.3

面向 AI Agent 的 Windows 文件操作层，MCP + CLI 双形态。本版修的是「工具自己说不清、说不全」的问题。

## 一行安装

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://github.com/tokenis2023/agent-ops/releases/latest/download/install.ps1 | iex"
```

自动完成：下载最新版 → SHA-256 校验 → 安装到 `%LOCALAPPDATA%\fsops` → 加入用户 PATH → 注册检测到的 Claude Code / Hermes / Codex。

卸载：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://github.com/tokenis2023/agent-ops/releases/latest/download/uninstall.ps1 | iex"
```

## 本版重点

### schema 不再漏字段

`fs_edit` 的 `files[].edits` 此前只有一个空对象，模型做批量编辑时看不到 `old/new/all/start/end`，只能猜。现在两处共用同一份 schema，并加了回归测试防止再次漂移。

### 能力能被发现

规则正文与 `initialize.instructions` 补上三组用法：

- `fs_grep` 拿行号 → `fs_read start=N block=true` 一次取回整个代码块
- `fs_edit` 的 `start`/`end` 限定行范围，只改重复字面量中的一部分
- 统计命中用 `fs_grep output=count`（不受 `limit` 截断）

### 错误能照着做

- `integrate --check` / `--remove` / `--dry-run` 不再强制同时给 `--rules`
- `--check` 状态改为中文（`无块`/`过期`/`损坏`），与 `doctor` 一致
- `--check` 比对正文而非只看标记：升级后规则变化会报「过期」
- 0 字节 DOCX/PDF 报「文件为空（0 字节）；可能下载或生成未完成」
- `install.ps1` 失败给出 `E_VERSION` / `E_INSTALL_DIR` / `E_NETWORK`，不再抛 PowerShell 堆栈
