# fsops v0.4.1

面向 AI Agent 的 Windows 文件操作层，MCP + CLI 双形态。本版不加新工具，把「多一轮、看不懂、静默改数据」这三类残留摩擦一次收掉：输出与错误自带可重放下一步，正文严格等于原文，schema 与运行时/文档/插件全面对齐。


## 减轮次：输出自带可重放下一步

- `fs_read reads` 模式的续读尾注带各自路径，多条「同 path」不再无法对应文件。
- 长行截断尾注给出被截行号、单行成本与 `重读该行: fs_read path=… start=N end=N max_line=0 budget≈M`，一次就能照抄重放。
- `fs_glob` / `fs_grep` 分页尾注从裸 `next_offset=N` 改为 `续读: fs_glob offset=N` / `续读: fs_grep offset=N output=<mode>`，并标注单位（匹配条目 / 命中 / 匹配文件），翻页不必回查 schema。
- `E_STALE` 统一为可复制的重试指令（`expect_hash=<新 hash>`）；`E_BATCH_PARTIAL` 列出已写路径并提示仅对剩余文件重发；`E_ENCODING_LOSS` 点名已有的 `fs_file op=convert encoding=utf-8`；`E_DOCX` 警告整体重建会丢光格式/图片/表格并给出重建命令形状。
- `E_NO_MATCH` 完全落空时给文件行数与开头锚点，范围无命中时列出命中行号；`E_LOCKED` 说明已等待时长、本次未写入、参数不变直接重试；repo map 截断尾注给出「调大 budget 或 fs_glob focus=<词> 缩小」。

## 正文与数据的确定性

- `fs_read` 正文逐行原样输出，删除了默认折叠连续空行的行为 —— 读到的片段可直接当 `fs_edit` 的 `old`，不再因缺行触发 `E_NO_MATCH`。
- 主路径与超大文件窗口分支的 `utf-8-lossy` 都显式警告：正文里的 U+FFFD 是替换字符、不是原文，切勿据此写回。
- `E_MIXED_EOL` 归一到原文件主换行风格（多数行使用的风格，平局取 LF），CRLF 仓库不再被整文件改成 LF 产生巨大 diff。
- `fs_exec` 后台任务超 64KB 的丢弃字节会在轮询里显式报告，并说明输出不完整、勿据此判断成败。
- `dry_run` 不再抢占独占写锁，预演不会与真实写入互斥白等 3 秒。

## 契约与 schema 可见性

- `validate_args` 在入口执行 schema 声明的 `required` / `enum` / `minimum` / `maxItems` 与数组项必填，非法调用一次给可复制修法；schema 生成不再覆盖显式 `minimum`。
- `fs_grep` 新增 `max_line`（默认 240 与 `fs_read` 一致，`0` 不截断），命中长行一次拿全，移除硬编码 200 字符窗口。
- `fs_edit` 描述补上正则替换能力；`force` / `reads` / `detail` 描述与实际行为和文档对齐。
- `fs_stat` 路径统一用双引号包裹，含空格路径可稳定切分（其余紧凑字段与 `hash=` 位置不变）。
- `install.ps1` 升级后提示新开会话或 `/reload-mcp`、清 `mcp_schema_cache.json`，并用 `fs_stat detail=server` 自检连的是哪一版。

## 宿主与文档

- DSH 插件不再暴露 `background`/`job`/`list`/`wait_ms`/`kill` 五个在该形态必然 `E_NO_JOB` 的参数；`program` 与工具级描述同步说明。
- DSH 冒烟测试改为「MCP 键是 DSH 键的超集、允许缺失仅限这五个」，并新增 description 能力词比对，把已发生过的 schema 漂移变成红灯。
- DSH 包 `files` 补齐 `docs/` 与根目录文档，README 相对链接在包内不再 404。
- README / 使用指南 / 工具参考 / package.json 与本版行为逐条对齐；8 轮修复全程 TDD，全量门禁（fmt、clippy、cargo test、185 项真实 MCP e2e、任务基准、DSH 冒烟）保持全绿。
