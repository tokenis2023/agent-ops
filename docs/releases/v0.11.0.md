# fsops v0.11.0

面向 AI Agent 的 Windows 文件操作层，MCP + CLI 双形态。本版是易用性专项：引导收敛（−21%）、错误恢复不再诱导跳过核对、截断与预算契约补齐。

## 一行安装

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/install.ps1')).TrimStart([char]0xFEFF)))"
```

卸载：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/uninstall.ps1')).TrimStart([char]0xFEFF)))"
```

## 本版改动

**引导收敛**

- `initialize.instructions` 1,262 → 997 B（−21%），只留路由与策略；参数级事实收归工具描述。
- 规则块 2,850 → 1,978 B；两份引导字符级重复率 47.1% → 19.6%。
- `fs_read` 描述把常用四路径前置；`fs_edit` 补 `diff=true`；`fs_grep` 补 count 统计口径。

**错误恢复**

- `E_STALE` 先核对内容再给新 hash，不再诱导跳过核对覆盖外部改动。
- `E_AMBIGUOUS` 顺序改为「加上下文 → 限定范围 → 确认才用 `all=true`」；候选片段按 1,200 B 预算。
- `E_NO_MATCH` 给出相似行总数；`E_LOCKED` 加「连续两次仍被占就停止」的停止条件。
- `fs_write files` 中途失败改用 `E_BATCH_PARTIAL` + 已写清单。

**预算与截断**

- 修复 `fs_inspect` 的 `time_budget_ms` / `no_ignore` 不可达（schema 未声明）。
- `reads` 顶层 `max_line`/`scan` 传播到每项。
- `reads`+`tail`、`block`+`ranges` 不再静默忽略，改报 `E_BAD_ARGS`。
- 工具参考新增四种截断信号的区分表与「offset 不是快照」声明。

**测试**

- 383→401 单测、186→213 e2e、9→10 基准场景；原 9 场景指标逐字不变。

**升级注意**

- `reads`+`tail` 与 `block`+`ranges` 现在报错（以前静默忽略）；`fs_write files` 中途失败错误码改为 `E_BATCH_PARTIAL`。
- 完整说明见 `CHANGELOG.md` 与 `docs/Agent易用性评测基线.md`。

> 本版所有行为变更都有确定性断言；真实模型侧的效果未做对照，不声称提升。
