# fsops v0.7.0

面向 AI Agent 的 Windows 文件操作层，MCP + CLI 双形态。本版重点是让工具在出错时把话说对：修掉一处会静默写坏文件的编辑歧义，把 DSH 插件单次调用从 ~33ms 降到亚毫秒，并让工具定义只保留 Rust 一份真源。

## 一行安装

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/install.ps1')).TrimStart([char]0xFEFF)))"
```

卸载：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/uninstall.ps1')).TrimStart([char]0xFEFF)))"
```

## 本版改动

### 修（会误导或静默出错的）

- `fs_edit` 同时给 `old` 与 `pattern` 时不再静默只执行 `pattern`（旧行为写盘内容错且零信号），改为 `E_BAD_EDIT` 互斥报错
- `E_AMBIGUOUS` 的建议改成可照做的写法：`all`/`start`/`end` 属于 `edits[]` 内的单条修改项
- `fs_exec` 非零退出不再冠 `ok` 前缀（`ok exit=3` → `exit=3 非零`），不再让编译/测试失败看起来像成功
- 多编辑中途失败时，错误里的文件片段标注「内存中间态，本次未写入任何文件」
- 缺文件/目录时追加 `fs_glob` 定位建议；路径里的 `$env:NAME` / `%NAME%` 直接点破「不会被展开」
- 修掉一个从未生效的判定：比较串少了「的」，导致 os error 3 的提示分支永远不命中

### 快

- DSH 插件复用一条长驻 `fsops mcp` 会话：`fs_read` 33.5ms → **0.54ms**、`fs_stat` 32.9ms → **0.34ms**，4 路并发一轮 0.59ms；会话故障自动退回一次性调用

### 稳

- 插件核对二进制版本，不符不再静默降级（`E_VERSION` 并给出三种修法）
- `fs_write` 全量覆盖不再被源文件混合换行拦住；`fs_edit` 同时命中陈旧与混合换行时先报 `E_STALE` 并一次说清
- `max_output` 低于下限 1024B 时回显实际生效值，不再静默抬高
- 工具定义改由 `fsops schema` 生成（`scripts/gen_dsh_specs.mjs`），冒烟测试加漂移守卫，不再三处手写
- 上述行为都在 `tools::call` 内核层，MCP / CLI / DSH 三类客户端一致生效
