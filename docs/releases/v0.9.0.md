# fsops v0.9.0

面向 AI Agent 的 Windows 文件操作层，MCP + CLI + DSH 插件三形态。

本版新增第 9 个工具 **`fs_inspect`**（一次看清目录），并修掉真实 A/B 实测暴露的两处返工点。
延续 v0.8.0 的目标：**减少 Agent 轮次**——每多一轮，整个上下文都要重发一次。

## 本版改动

### 新工具：`fs_inspect`

一次给出「文件规模 + 可选正则的命中分布 + 命中样例」，替代
「先 `fs_glob` 看结构、再 `fs_stat` 查大小、再 `fs_grep` 找目标」的探索链。

```text
fs_inspect {path: "src", pattern: "E_BAD_REGEX"}

ok 22 个文件 725.9K
最大：tools.rs 295.3K, search.rs 82.9K, edit.rs 43.8K …
命中 `E_BAD_REGEX`：3 文件 14 处 → edit.rs:5, search.rs:5, tools.rs:4
样例：
  edit.rs:269 "E_BAD_REGEX 第{ordinal}处 pattern 无效: {err}；{}",
  …
如需细节：fs_read 目标文件，或 fs_grep expand=block 直接取整块
```

- 规模同质的仓库**不堆体积清单**（只报「规模接近」），避免十几个等大文件的纯 token 浪费。
- 命中分布条数跟随 `limit`，不会在拿到全部文件名前截断。
- `focus` 让关键词命中的文件优先于体积排序。

### 减少返工

| 问题 | 依据 | 修法 |
|---|---|---|
| `fs_edit` 顶层单条修改简写被拒 | 三次独立真实任务 **3/3** 都把 `pattern`/`all` 放顶层，每次被拒后重试，白费一轮 | 单条修改时顶层 `old`/`new`、`pattern`/`replacement`、`all`、`start`/`end` 直接生效；给了 `edits`/`files` 时仍强制嵌入 |
| `fs_inspect` 命中分布写死 8 条 | A/B 两侧都报告「第 8 个后截断，调 limit 也不展开」，于是仍要补一次 `fs_grep` | 跟随 `limit`（默认 15，上限 40） |

### 防漂移

- 插件形态的参数裁剪改为单一真源（`dsh/excluded.js`），生成器与运行时共用。
- 冒烟测试 77 → 92 项：schema 不声明被剔除参数、描述不教模型用它、运行时真的拒绝、
  `dsh/` 下每个模块都在包清单里。
- CI 增加 `gen_dsh_specs --check` 与「release 二进制再过一遍插件冒烟」。

### 验证

- `cargo test --lib`：382 通过
- 真实 MCP e2e：185 项
- DSH 插件冒烟：92 项
- `scripts/check.ps1 full`：全绿

## 从 0.8.0 升级

插件与内核**必须同版本**：工具定义由 `fsops schema` 生成，只换插件不换内核时，
新工具/新参数会被旧内核拒绝。

- 用 install.ps1 或 `fsops upgrade` 升级二进制；
- DSH 插件把 pin 改为 `#v0.9.0` 后重装；
- 自检：`fs_stat detail=server` 应返回 `fsops 0.9.0 tools=9`。
