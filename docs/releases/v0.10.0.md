# fsops v0.10.0

面向 AI Agent 的 Windows 文件操作层，MCP + CLI + DSH 插件三形态。

**次版本**：DSH 插件形态放开 `fs_exec` 后台任务（长命令不再卡住整个回合），
并修掉「宿主断开后前台命令变僵尸进程」——宿主取消后子进程曾会跑满 `timeout_ms`
（最长 10 分钟）才收工。工具面仍是 9 个，未新增工具。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/install.ps1')).TrimStart([char]0xFEFF)))"
```

## 本版改动

### 新能力：DSH 插件形态放开 `fs_exec` 后台任务

原先插件形态屏蔽了 `background`/`job`/`list`/`wait_ms`/`kill`，理由是「job 生命周期绑在
长驻会话，插件重载后失效」。实际代价更大：**长命令（构建 27s、完整检查 40s）必然前台阻塞，
整个工具面被占住，UI 上表现为长时间卡住，用户和模型都判断不出是慢还是死了。**

反过来看，长驻会话恰恰是承载后台任务最合适的地方——它能活到任务结束。本版放开：

- `dsh/excluded.js` 的 `EXCLUDED` 清空（机制保留，供将来真正不支持的参数用）；
- 生成的 schema 重新包含这 5 个参数，描述改为教模型怎么用（起任务 → `wait_ms` 等结果）；
- 实测：`background=true` **6ms 返回 job id**，期间其它调用不受影响，`wait_ms` 一次等到退出。

配套修正：

- **会话 LRU 回收时跳过有后台任务在跑的会话**——否则 `dispose()` 会静默杀掉用户正在等的构建；
- 冒烟测试语义反转：从「必须拒绝后台参数」改为「必须暴露且真能跑通」。

已知边界：job id 绑在当前工作目录的会话上，切目录或插件重载后失效。

### 修复：宿主断开后前台命令不再变僵尸进程

宿主取消/回收长驻 `fsops mcp` 会话时，正在跑的前台 `fs_exec` 原先会一直跑到自己的
`timeout_ms`（最长 10 分钟）：`serve_parallel` 读 stdin 到 EOF 后只是 `drop(tx)` 再 `join`
工作线程，子进程没人管；写响应失败也被忽略。宿主早就走了，进程树还活着。

现在：

- `exec::run_with_cancel` 接受取消信号，置位后结束进程树并返回 `E_ABORTED`；
- MCP 层起 250ms 的宿主存活检测线程：对 stdout 管道做**零长度 `WriteFile`**，对端关掉后
  必然失败 → 置位全局取消标记。用零长度写而不是 `PeekNamedPipe`，是因为后者在普通文件
  stdout 上本来就报 `ERROR_ACCESS_DENIED`，分不清「不是管道」和「断了」；且对端关闭后
  `GetLastError` 仍可能是 0，所以只看返回值；
- **`stdin` 读到 EOF 不算宿主已走**：一次性 `fsops call` 与 e2e 客户端都是写完就关 stdin，
  此时管道里排队的请求仍必须执行完；
- 取消后不再等管道排空（宿主已经走了，没人要结果），超时仍照旧读空；
- **实测：宿主断开后 0.7s 内子进程被结束**（原先要等满 30s 的 `ping`）。

新增单测「宿主断开时前台命令被提前结束」与 e2e「宿主断开后前台命令立刻收工」；
`E_ABORTED` 已补进工具参考与使用指南的错误码表。

## 从 0.9.1 升级

插件与内核**必须同版本**（工具定义由 `fsops schema` 生成）。

- 用 install.ps1 或 `fsops upgrade` 升级二进制；
- DSH 插件把 pin 改为 `#v0.10.0` 后重装；
- 自检：`fs_stat detail=server` 应返回 `fsops 0.10.0 tools=9`。
