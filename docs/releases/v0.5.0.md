# fsops v0.5.0

面向 AI Agent 的 Windows 文件操作层，MCP + CLI 双形态。本版把 `fs_grep` 的并行从「手动开关」升级为「按仓库规模自动选择」，修掉 `fs_exec` 的 cwd 路径不一致与 PowerShell 5.1 下的安装 BOM 问题。

## 一行安装

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/install.ps1')).TrimStart([char]0xFEFF)))"
```

自动完成：下载最新版 → SHA-256 校验 → 安装到 `%LOCALAPPDATA%\fsops` → 加入用户 PATH → 注册检测到的 Claude Code / Hermes / Codex。

卸载：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/uninstall.ps1')).TrimStart([char]0xFEFF)))"
```

## 搜索默认自动并行

- `fs_grep` 的 `parallel` 改为三态：省略即自动，`true` / `false` 仍可强制。
- Auto 的取舍：先逐个串行扫描，完整保留串行路径的「满页即停」——达到 limit 后不再访问后续目录项，小仓库也不起线程；攒满一波候选（线程数 × 16，上限 128）证明是大仓库后，剩余文件走并行波次。
- 输出与串行逐字节一致：三种模式共用同一套扫描与合并逻辑，单测覆盖边界文件、分页参数与 count 聚合。
- 实测（release 二进制，5 次中位）：

| 仓库规模 | 串行 | 自动（默认） | 强制并行 |
|---|---|---|---|
| 40 文件 | 6.3ms | 5.9ms | 4.3ms |
| 500 文件 | 52.6ms | 31.9ms（1.65×） | 25.5ms |
| 3000 文件 | 330.3ms | 178.7ms（1.85×） | 166.8ms |

## 修复

- `fs_exec` 的 `cwd` 不再原样交给 `current_dir`：`/d/repo` 这类 POSIX 写法此前报 `os error 267`，还把目录问题误导成 PATH 问题。现与文件工具共用同一套路径解析（POSIX / 原生 / `~/` / 相对路径），目录不存在时返回 `E_BAD_ARGS` 并给出实际解析结果。
- 一行安装命令在 Windows PowerShell 5.1 下因 BOM 解析失败：`irm` 会把 UTF-8 BOM 解成 `ï»¿`，导致 `[CmdletBinding()]` 不再是首语句。改用 `Net.WebClient` 取原始字节 + UTF-8 解码 + 去 BOM + `scriptblock::Create`，README / 使用指南 / 安装脚本示例同步。

## 契约与文档

- `fs_grep` 的 schema 描述说明三态语义；DSH 插件描述同步，冒烟测试继续比对参数集合与描述能力词。
- `工具参考` 的 `parallel` 与 `cwd` 说明更新；`AGENTS.md` 不再建议手动设 `parallel=true`。
- `check.ps1 full` 七项门禁全绿：fmt、clippy、340 个单测、185 项真实 MCP e2e、任务级基准、DSH 冒烟。
