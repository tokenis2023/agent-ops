# fsops v0.2.2

面向 AI Agent 的 Windows 文件操作层，MCP + CLI 双形态。本版聚焦「少一次往返、少一点 token、错误能照着做」。

## 一行安装

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://github.com/tokenis2023/agent-ops/releases/latest/download/install.ps1 | iex"
```

自动完成：下载最新版 → SHA-256 校验 → 安装到 `%LOCALAPPDATA%\fsops` → 加入用户 PATH → 注册检测到的 Claude Code / Hermes / Codex。

卸载：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://github.com/tokenis2023/agent-ops/releases/latest/download/uninstall.ps1 | iex"
```

## 本版重点

### 少一次往返

- `fs_read block=true` 返回**包含** `start` 行的整个代码块：命中行在函数内部时向前找块起始、向后配平结束。`fs_grep` 给行号 → `fs_read block=true` 两步拿到完整函数，不再靠猜 `end`（实测 170 行的函数一次到位）。
- `fs_edit` 的 `edits` 支持 `start`/`end` 行范围：同一个字面量在文件里出现几十处时，配合 `all=true` 只改指定区间，不必为每处构造不同上下文。

### 错误能照着做

- `E_ENCODING_LOSS` 报出具体字符、码位与行号：`U+1F600 '😀'（第 3 行）`。
- `E_LINE_TOO_LONG` / 长行尾注给出所需 `budget` 数值（如 `budget≈112200`），不再只建议「用 max_line=0」——单行文件常有上百 KB，照做会撞进死循环。
- `E_READ` 遇到双重盘符路径（`/d/c/Users/x`）指出格式问题并给出正确形式。
- `E_TOO_LARGE` 超大文件提示改为「先用 `fs_grep` 定位行号，再用 `start`/`end` 读取该区间」。
- `doctor` 区分「规则文件不存在」与「文件存在但没有 fsops 块」——此前都报「缺失」，会诱导模型整文件覆盖用户已有的 `AGENTS.md` / `CLAUDE.md`。

### 统计与截断不再骗人

- `fs_grep output=count` 默认不受 `limit=100` 截断（此前 203 处命中会报成 100）；显式传 `limit` 时仍截断并标注。
- `fs_glob` 预算截断时说明「已给 N 条（共 M 条匹配）」。

### 文档与基准

- `docs/工具参考.md` 补齐全部 42 个错误码的含义与下一步动作（此前只散落提到 10 个）。
- `python tests/bench.py` 无需外部仓库、无需 tiktoken 即可运行，并接入 CI 自检；README 基准表换成可复跑数据。

## 实测

内置 fixture（40 文件 / 每文件 36 行）：合计 12,184 → 2,015，省 **83.5%**。
真实仓库（fsops 自身）：合计 84,326 → 994，省 **98.8%**。

纯定位单行时为 **−2.6%**（工具输出带路径头），README 已如实列出。
