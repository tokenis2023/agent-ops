# Agent 运行时优化第二批设计

## 目标

继续减少大文件与大面积搜索中的 CPU、内存和无效扫描，并让 Agent 引导与新能力保持一致。保持 6 个工具和现有正常输出契约。

## 范围

1. 正则编辑改为单趟流式构建，消除逐命中从范围起点数换行的 O(n²)。
2. 搜索不再把每个文件复制成逐行 `String`，改用全文 + 借用的 `Vec<&str>`。
3. 并行 grep 改为有界波次处理，不再预先收集最多 10 万候选文件；达到 limit 可停止遍历。
4. `fs_read` 每个文件只建立一次行索引，预算收敛、行数、block 和 ranges 共用。
5. initialize instructions 与受管规则统一 PDF 路由，并写入正则编辑、`diff=true` 的用法。

## 非目标

- 不改变 >32 MB 大文件的 hash/总行数精确契约；快速窗口另批处理。
- 不新增工具、缓存、语法树或持久索引。
- 不修改写盘、编码、EOL 与并发保护语义。

## 设计

### 正则编辑

`apply_regex` 用游标单趟扫描 capture：

- `line_cursor` 记录已统计到的字节位置，`line_no` 只向前累加换行。
- 输出 StringBuilder 直接拼接未变片段与展开结果，不再收集全部命中字符串。
- 只保留前 `MAX_HUNKS` 的 old/new 供 diff，其余仅计数。

正确性用“跨行匹配后的行号”“大量替换仍线性”两类测试锁定。

### 搜索文本

`load_search_text` 返回拥有的 UTF-8/DOCX/PDF 正文；扫描函数在正文生命周期内构造 `Vec<&str>`，不再为每一行分配 `String`。选中的命中行才按需生成展示文本。串行和并行共用同一行切分规则。

### 并行 grep 流水线

遍历回调按路径顺序累积一个固定大小波次，达到波次后立即并行扫描并在回调内按序合并；达到全局截断条件返回 `VisitControl::Stop`。内存上限从“候选文件总数”降为“一个波次”，并保留：

- 路径稳定顺序；
- 串行/并行逐字节一致；
- limit/offset/max_per_file 语义；
- 时间预算与单文件内部截止检查。

### 行索引

`render::LineIndex` 在单个文件的一次读取中只构建一次，提供总行数、行切片与按 ranges 渲染。`fs_read` 的行数统计、block 探测、预算多轮收敛复用同一索引。现有 `render_ranges(text, ...)` 保留为测试/兼容包装。

### Agent 引导

统一写清：

- DOCX/PDF 正文走 `fs_read`；只有图片和不支持的二进制回退宿主。
- 只知道文本形状时用 `fs_edit pattern/replacement`，不要先读全文抄原文。
- 结构调整后用 `diff=true` 自查，避免再读全文。

## 验证

- 每项先写失败测试并确认 RED。
- 新增：正则大文件线性测试、并行提前停止的 entries_visited 断言、行索引单次构建计数器、引导文本断言。
- 最终运行 fmt、clippy、完整 Rust 测试、真实 MCP e2e、bench。
- 不提交、不推送、不发版。
