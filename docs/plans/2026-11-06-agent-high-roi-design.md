# Agent 高 ROI 优化设计

## 目标与范围

减少 fsops 在真实 Agent 任务链中的重复读取、重复扫描、错误续读和无效重试。本批只做：

1. `fs_grep` 的 `files/count` 专用执行语义。
2. `block=true`、glob、长行预算的可重放续读。
3. 严格参数校验与 `fs_stat` 数量上限。
4. `fs_stat` 普通文本单次读取。
5. `walk::visit` 的遍历内部时间预算。

不做并行搜索流水线、行索引重构、大文件快速预览、新工具、持久缓存和发版。

## 方案比较

- A：只压缩输出文案。改动小，但无法减少重扫和错误往返，不采用。
- B：保持 6 个工具，在执行内核与续读契约内修复任务链。收益直接、兼容面可控，采用。
- C：引入缓存、语法树和全新游标服务。复杂度和失效风险高，本批不采用。

## 架构与数据流

### 搜索

把 `GrepOutput` 传进搜索执行层，而不是只在渲染层使用：

- `files`：每个文件只保留第一次命中；`limit/offset` 按文件计数；实际观察到下一个命中文件才返回 `next_offset`。
- `count`：只保存每文件聚合计数，不物化逐行命中正文；默认仍扫描完整结果集，超时时明确标注不完整。
- `matches/snippets`：保留现有按命中分页行为。
- 串行和并行必须返回相同结果；复用同一聚合结构，避免两条路径语义漂移。

### 续读与分页

- block 首次展开后固定 `(块起始, 块结束)`；预算截断时续读使用 `ranges=[[下一行,原块结束]]`，重放不再探测新块。
- glob 按完整条目渲染，禁止 UTF-8 截断路径；增加按匹配条目计的 `offset/next_offset`。
- glob 只有观察到额外条目才声明下一页；预算页推进量为实际完整输出的条数；空页不推进。
- 长行提示记录本响应所有截断行的最大原始字节数，建议预算覆盖该行及固定开销。

### 参数与错误

- 未知顶层字段报 `E_BAD_ARGS`，给最接近的合法字段。
- integer 只接受非负整数，不再把负数/浮点数退回默认值。
- `paths` 的元素类型错误必须显式报错。
- `fs_stat.paths` 最多 50 个，超限报错；schema 同步声明约束。
- 所有续读建议必须通过真实重放测试。

### I/O 与遍历

- 从已读 bytes 构造 Snapshot，stat 复用该快照，普通文本只读一次。
- `walk::visit` 每 256 个原始目录项及循环结束检查 deadline，不依赖 visitor 被调用。

## 兼容性与安全

- 不增加工具，不改变 `matches/snippets` 的正常输出。
- `files` 的分页单位修正为文件，属于对现有高密度命中场景的错误语义修复，文档同步说明。
- 写入路径不改；原子写、编码和 EOL 保护保持不变。
- 不提交、不推送、不打 tag、不发版。

## 验证策略

每项先做失败测试并确认 RED，再写最小实现到 GREEN。重点覆盖：

- 高密度首文件不能挤掉其他 `files` 结果。
- files/count 串行与并行一致，count 不保存逐命中正文。
- block 跨页行集合无重复、无遗漏。
- glob 预算页没有半路径，offset 重放无重复。
- 长行提示预算可以照抄成功。
- 错误参数不会静默执行默认行为。
- stat 单次读取由测试计数器验证。
- visit 在 visitor 不被调用时也能超时。

最后运行 `cargo fmt --all -- --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`、`python tests/windows_semantics.py` 和 `python tests/bench.py`。
