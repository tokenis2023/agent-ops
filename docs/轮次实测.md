# 轮次实测：工具改造对 Agent 调用次数的影响

> 结论先行：**token 就是钱，而每一轮都要重发整个上下文（含约 6.5k token 的常驻工具 schema）。**
> 一次工具输出只有几百 token，一轮上下文是几万 token——**省输出没意义，省轮次才有意义**。

本文记录的是"减少轮次"系列改造的实测数据，不是估算。

## 方法

用**真实 Agent**（不是脚本回放）在同一套 fixture 上完成同一任务，逐次记录工具调用。
关键设计：两侧 fixture 内容逐字节相同，任务书相同，唯一变量是**工具是否可用/是否易用**。

fixture（14 个文件）：12 个 `src/svcNN.ts`（各含一个 `export function handle_svcNN`）
+ `src/log.ts`（含一处 `console.log`）+ `README.md`。

任务：① 仓库有多少文件、总大小？② 哪些文件含 `handle_` 导出？③ 把 `log.ts` 的
`console.log` 改成 `console.error` 并确认生效。

## 实测结果

### 1. `fs_inspect` 有无对照（v0.9.0，同模型同任务）

| | 有 `fs_inspect` | 无 `fs_inspect` |
|---|---|---|
| 调用次数 | **4** | **5** |
| 失败次数 | 0 | 0 |
| 输出字符 | 981 | 859 |

调用序列：

```text
有:  fs_inspect(规模+命中分布+样例)  → fs_edit → fs_grep → fs_write   = 4
无:  fs_glob(规模) → fs_grep(命中)  → fs_edit → fs_grep → fs_write   = 5
```

**结论**：`fs_inspect` 把「`fs_glob` + `fs_grep`」合成一次，**省 1 轮**；但它自身输出
比那两个加起来多 122 字符（多给了样例）。本质是"2 合 1"，不是质变。

### 2. `fs_edit` 顶层简写（v0.8.0 → v0.9.0）

同任务三次独立运行（不同 agent、不同 fixture 路径），**3/3** 都把 `pattern`/`all`
直接放顶层，被 `E_BAD_ARGS` 拒绝后重试——每次白费一轮。

改成接受顶层简写后的复测：

| 版本 | A 侧 | B 侧 |
|---|---|---|
| v0.8.0（修复前） | 5 次，**1 次失败** | 7 次，**1 次失败** |
| v0.9.0（修复后） | 4 次，0 失败 | 5 次，0 失败 |

**结论**：这类"模型自然写法被工具纠正"的坑，每次踩到就多一轮；改成接受后归零。

### 3. 其它改造的收益来源（机制明确，未单独做对照）

| 改造 | 机制 | 省轮 |
|---|---|---|
| `fs_write files` 批量 | 建 N 个文件从 N 次变 1 次 | **N−1** |
| `fs_grep` 首行带分布摘要 | 替代 `output=files` + `output=count` 两轮 | 1–2 |
| `fs_grep expand=block` | 合并「grep 拿行号 → `fs_read block=true`」 | 1 |
| `fs_grep` 默认 limit 100→200 | 少一次 `offset` 翻页 | 1（边界时） |
| `fs_edit` 半行 `old` 警告 | 消掉「改完不自知 → 下轮 fs_read 发现 → 再改」 | 2–3（踩坑时） |

## 诚实的评估

- **除批量写入外，其余每项都是"省 1 轮"级别的改进，不是数量级提升。**
- 对真实文件密集型任务（原 57 次调用）的累计效果约 **57 → 39 轮（−32%）**，
  主要贡献来自 `fs_write files` 批量那一项。
- `fs_inspect` 的固定成本是 +276 token/轮常驻 schema；20 轮任务约 5.5k，
  用一次省 20k+，**用一次就回本**，但收益幅度有限。
- 每次实测每侧只有 1 次运行（n=1），模型行为有方差；上面标注为"对照"的两项
  是同模型同任务，可比性最好。

## 复跑方式

需要一个真实 Agent 环境（本仓库的评测流程用 DSH 的 subagent）：

1. 按上文造两个内容逐字节相同的 fixture 目录；
2. 给两个 agent 相同任务书，一侧禁用 `fs_inspect`（或在旧版本上跑）；
3. 让 agent 把每次调用记进报告，对比调用次数与失败次数。

注意：这类测量的**变量是模型行为**，只能靠"同模型 + 同任务 + 同 fixture"控制，
不能像 `tests/bench.py` 那样在 CI 里机械复跑。
