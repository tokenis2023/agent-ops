# 设计：为什么是这 6 个工具、为什么用 Rust

## 出发点

参考 [dsh-ops](https://github.com/T-Auto/dsh-ops) 的思路：**token 效率来自"少返回、少轮次"，
而不是"多给模型几个工具"**。dsh-ops 是 JS 插件，只能服务自家 harness；这里换成 MCP + CLI
双形态，让同一份实现能接进任何 agent。

Rust 不是为了性能数字好看，而是三个具体收益：

1. **冷启动**：MCP stdio 模式下，每次工具调用都可能起一个新进程。Node 起步 80–150 ms，
   约 2 MB 的静态 Rust 二进制实测 ~10 ms。一个 200 次工具调用的任务，差出 20 秒以上。
2. **单文件分发**：`fsops.exe` 拷过去就能用，没有 node_modules、没有 venv。
3. **文件系统细节可控**：GBK 解码、BOM、`\\?\` 长路径、共享冲突重试、原子替换，
   这些用标准库能精确写出来，不用看运行时的脸色。

## 输出是给 AI 读的，不是给人看的

这条是全部取舍的总纲。人类友好的输出（完整路径、礼貌措辞、进度条、对齐表格）对模型是纯噪声；
模型需要的是**最小充分信息 + 稳定可解析的结构 + 可执行的下一步**。

具体判据：

1. **信息密度优先**：省掉只有人才需要的东西。多文件读取时公共目录前缀只写一次并声明省略了什么
   （5 个深层文件从 2.7 KB 压到 0.9 KB）；能一行说清就不写两行。
2. **机器可解析**：输出以稳定错误码开头（`E_XXX`），字段用固定分隔符。不要散文式描述，
   否则模型得先理解自然语言再提取信息。
3. **错误必须可执行**：只说「哪错了」不够，要给「怎么修」。例如 glob 当正则写时给出正确的
   正则等价写法；只读文件给出取消只读属性的命令；截断时给出续读参数和 `max_line=0`。
4. **禁止静默降级**：参数类型写错、漏写必填字段、超预算截断，一律显式报错或提示。
   悄悄退回默认值是最危险的失败模式——模型以为参数生效了，却拿到不同行为，
   于是基于错误前提继续推理。
5. **省略必须声明**：能省的只有冗余；省了就要说清省了什么（如「以下路径省略公共前缀 X」），
   否则模型会把 `a.txt` 误读成相对当前目录。
6. **宁可多一行提示，不让模型多一次往返**：省 token 的目标是省「总消耗」，不是省「单次字节」。
   一次多余的探测请求（读盘 + 上下文）远比一行提示贵。

## 工具面为什么是 6 个

工具每多一个，系统提示词就多一段 schema（实测 6 个工具 5.5 KB），
而且模型选错工具的几率上升。因此：

- 读：`fs_read`（含多文件、行范围）—— 不要 `cat`、`head`、`tail`、`read_lines`
- 改：`fs_edit`（含批量、dry_run、并发保护）—— 不要 `replace`、`insert`、`patch_file`
- 写：`fs_write`（原子、沿用编码）
- 找：`fs_glob`（按名字）+ `fs_grep`（按内容）—— 职责清晰，模型不会混
- 看：`fs_stat`（元信息 + hash）

`rm/mv/cp/mkdir` 不进工具面：宿主 shell 已经能做，而且这四类操作在 Windows 上几乎没有
"模型写不对"的痛点（不像路径和换行）。

## 输出的三层预算

| 层 | 规则 | 目的 |
|---|---|---|
| 结构 | `行号\|内容`，不用 JSON 逐行对象 | 同样内容省 50%+ 字符 |
| 细节 | 连续空行折叠为一条；>240 字符的行截断并标注 `…(+N字符)` | 把 token 留给有效信息 |
| 预算 | 单次返回硬上限（默认 12 KB），超出给 `续读: fs_read path=… start=…` | 让模型一次拿够、又不撑爆上下文 |

`fs_edit` 的返回是这条原则的极端情况：`ok 3 处修改 (+8 -3) @ 12,40-52,88 hash=…` 共 63 字节。
对照"读全文 + 写全文"的 baseline（本仓库实测 29,722 token），这是 99.6% 的差距。

## Windows 语义的四个决定

1. **路径展示用 POSIX 形式**（`/d/repo/x`）：模型对斜杠路径的先验最强，报错也更容易自纠。
   传入时四种形式都接受，避免模型"学一套新写法"。
2. **换行在匹配层归一，在落盘层还原**：`old_text` 里带 `\n` 也能命中 CRLF 文件；
   写回时按原文件的 EOL 还原，不把整个仓库的换行改掉（git diff 会炸）。
3. **编码识别顺序**：BOM → UTF-16 交错零字节特征 → UTF-8 校验 → GBK → GB18030 → lossy。
   中文环境里 GBK 必须排在 lossy 前面，否则一次误判就把注释写坏。
4. **写入一律临时文件 + fsync + 改名**：Windows 的 rename 覆盖是原子的。这样 crash 不会留
   半截文件；同时按 15/40/120/300 ms 退避重试，绕开编辑器和杀软的短暂独占。

## 错误信息的价值

模型改错代码后的重试循环，比一次成功的调用贵得多。所以：

- 歧义（同一片段出现多次）→ `E_AMBIGUOUS … 行 12,40`，让它补上下文或显式 `all=true`
- 未命中 → `E_NO_MATCH` + 最接近的 5 行实际内容
- 并发改动 → `E_STALE 文件已变化（当前 hash=…）`，防止"读到旧内容后盲写"
- 超时 → 返回已找到的结果 + "缩小 path 或加 glob"，而不是干等

## 与 dsh-ops 的差异

| | dsh-ops | fsops |
|---|---|---|
| 宿主 | DeepSeek Harness 插件（JS） | MCP + CLI（任意 agent） |
| 运行时 | Node | Rust 单文件 |
| 文档解析 | 有（PDF/DOCX） | DOCX 正文读写；PDF 正文只读 |
| 工具隐藏 | 有（隐藏官方文件工具） | 无（不改宿主，只提供替代品） |
| TUI 面板 | 有 | 不做 |
