# 工具参考

fsops 通过 MCP stdio 暴露 8 个工具，也可以使用 `fsops call <tool> '<json>'` 调试。

## 通用约定

### 路径

全部接受：

```text
/d/repo/src/main.rs
/mnt/d/repo/src/main.rs
D:\repo\src\main.rs
D:/repo/src/main.rs
~/project/src/main.rs
相对当前目录的路径
```

输出统一显示为 POSIX 形式，例如 `/d/repo/src/main.rs`。

### 输出预算

读取和搜索有字节预算。超预算时返回续读参数，不会输出半截 UTF-8 字符。

### 内容指纹

`fs_read`、`fs_stat detail=hash/full`、`fs_edit` 会返回短 hash。把读到的 hash 传给写操作可以在文件被其他进程修改时得到 `E_STALE`。

### 错误

工具返回纯文本。以 `E_` 开头表示错误，MCP 响应同时设置 `isError=true`。

## fs_read

读取文本文件、DOCX 或 PDF 正文，返回元信息、行号和内容窗口。

### 参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | string | 单个文件路径 |
| `paths` | string[] | 一次读多个文件，最多 20 个，所有文件共用 start/end |
| `reads` | object[] | 一次读多个文件的**不同区间**，每项 `{path,start,end,ranges,block,max_line,scan,budget,focus}`；与 `path`/`paths`/`ranges`/`start`/`end`/`block`/`summary`/`focus` 互斥，最多 20 项；未给 `budget` 的项均分顶层预算，大文件可单项多要 |
| `start` | integer | 起始行，1 基 |
| `block` | boolean | 返回包含 `start` 行的整个代码块：向前找块起始、向后配平结束。配合 `fs_grep` 的行号用，命中行在函数内部也能展开 |
| `end` | integer | 结束行，闭区间 |
| `ranges` | array | 单文件多段区间，如 `[[1,20],[80,100]]`；优先于 start/end |
| `max_line` | integer | 每行最多字符数，默认 240；`0` 表示不截断 |
| `scan` | string | 仅对 >32 MB 文件生效：`window`（默认）只读到请求区间末尾并探测是否还有内容，毫秒级返回但不给全文 hash/总行数；`full` 全文件扫描，给精确 hash 与总行数 |
| `summary` | boolean | 只输出结构摘要：声明行 + 行号，不展开函数体；行号可直接接 `block=true` 读实现。与 `ranges`/`block`/`end` 互斥；数据文件与 >32 MB 文件不支持 |
| `tail` | integer | 只读最后 N 行（日志场景），文件不足 N 行时读全部；与 `start`/`end`/`ranges`/`block`/`summary`/`focus`/`paths` 互斥 |
| `focus` | string | 正则；只返回命中所在的完整代码块（自动展开、合并重叠区间），替代「先 `fs_grep` 再 `block=true`」两步。数据文件（JSON/YAML/Markdown 等）没有代码块，只给命中行 ±2 行。仅单文件，与 `paths`/`reads`/`ranges`/`start`/`end`/`block`/`summary` 互斥；最多 12 块；JSON 字符串里反斜杠需双写 |
| `force` | boolean | 读取缓存**默认关闭**；仅当 `FSOPS_MCP_CACHE=1` 开启后，用本参数绕过未变更摘要、强制返回正文。默认部署重复读直接返回全文，无需传（详见下方「说明」） |
| `budget` | integer | 响应字节上限，默认 32768（约 8K token）；错误消息保留最低可解析长度，不受极小值影响。单文件、未显式传 budget 且 ≤32 KB 时自动放开到全文（含行号开销） |

### 输出示例

```text
/d/repo/src/main.rs utf-8 CRLF 8.2K 240行 hash=1fc9f68801e1a113
40|fn main() {
41|    ...
```

一次读多个文件的不同区间：

```json
{"reads":[{"path":"/d/a.rs","start":10,"end":40},{"path":"/d/b.rs","start":1,"end":20}]}
```

只取某个模式的代码块（自动展开成完整函数）：

```json
{"path":"/d/a.rs","focus":"unwrap\\("}
```

超过 32 MB 的文件默认走快速窗口，头部会显式标注“未全扫”：

```text
/d/repo/data/huge.log utf-8 LF 48.0M 窗口扫描（未全扫，仅本次请求区间）；全文 hash/总行数用 scan=full 或 fs_stat detail=hash
1200|...
```

被预算截断时：

```text
… 1-129/240 行 | 续读: fs_read 同 path start=130
```

### 说明

- 模式表：`path` 与 `paths` 可同时给（并集，一次读多个文件）、`reads` 异构区间数组（与 `path`/`paths` 互斥）、按正则取块 `focus`、`tail=N` 读末尾、`summary` 只给声明行号（仅单文件，不能与 `ranges`/`block`/`end` 同用）。
- 超过 20 个文件会显式拒绝；预算不足时给一条 `E_BUDGET` 提示并建议分批，不会逐文件刷错误。
- `reads` 的输出首行是 `ok reads N 项：X 成功，Y 失败`——单项失败不影响其余项；MCP 的 `isError` 仍按整体保守置 true，先看首行判断还有多少内容可用。
- `fs_read` 的读取缓存默认**关闭**：stub 只省单次响应，却让模型多花一轮 `force=true`，而多一轮等于整个上下文重发。需要时用 `FSOPS_MCP_CACHE=1` 开启；开启后只有普通读取会建立/命中，`summary=true` 与 `focus` 不参与。
- 小文件（≤32 KB）在未显式传 `budget` 时自动放开到全文（并按行数补足行号开销），避免为几 KB 差异多一次续读。
- 常规文件一次读入，同时计算文档和 hash。
- 带 BOM 的 UTF-16/UTF-8 一律按文本处理，纯中文 UTF-16 不会被误判为二进制。
- 超长行（>200 字符）围绕命中位置开窗，两侧用 `…` 标出省略，命中词始终可见。
- `pattern` 是正则；写成 glob（`*.txt`）时错误里会给出正确的正则等价写法。
- 能匹配空位置的正则（`^`、`$`、`a*`、`.*`、`\b`）会被拒绝：它们命中每一行但没有筛选价值。
- 写入符号链接时改写真实目标，不再把链接替换成普通文件。
- 多文件读取时，深目录下的公共路径前缀只写一次并在开头声明（浅路径不启用，避免噪声）。
- 读取失败的错误里带出具体文件路径。
- 符号链接显示为 `link 0B ... -> 目标路径 目标大小`；链接自身的 0B 不代表目标为空。
- `+N -M` 表示改动了几行；同一行多处修改只计一次，替换次数另行说明。
- `block=true` 首次展开后固定原代码块边界；预算截断时尾注给出 `ranges=[[下一行,原块结束]]`，照抄续读不会重新探测内层块。纯文本等找不到代码块时回退为普通行区间并在头部明确提示（Python 等缩进语言没有花括号，block 不可用），续读的结束行会钳制为真实总行数，不会出现 `usize::MAX`。
- `tail=N` 免去「先 `fs_stat` 拿总行数再算 `start`」那一步；超大文件（>32 MB）不支持 tail，需先 `fs_grep` 定位或 `scan=full`。
- 多文件读取时续读尾注带各自路径（`续读: fs_read path=… start=N`），不再是一串看不出对应关系的「同 path」。
- `summary=true` 输出「行号|声明」的结构索引：按扩展名识别 Rust/Python/JS/TS/Go/Java/C#/C/C++/Ruby/Shell，跳过 Rust 的 `mod tests` 块。典型用法是先 `summary` 看地图，再 `block=true start=<行号>` 进房间，省掉为找位置而做的一次全文读取。摘要比全文还长时（极短的声明型文件）会明确说明并按全文返回。
- 预算截断时尾注给出的行号范围与实际输出的正文一致，可直接照抄续读参数。
- `ranges` 重叠时会自动合并，完全越界的区间会提示已跳过。
- 只读文件在编辑前预检，返回 `E_READONLY` 并提示去掉只读属性。
- 空文件返回 `0行` 且没有正文行；重复的 `paths` 会自动去重。
- 二进制文件（前 8KB 含 NUL 且不像 UTF-16 文本）返回 `E_BINARY`；UTF-16 文本正常读取。
- 多文件读取中任一文件失败（`E_BINARY`、`E_READ` 等）时，MCP 响应标记 `isError=true`。
- `.docx` 从 `word/document.xml` 抽取正文；表格单元格用制表符分隔，不解析页眉页脚、批注和图片。
- `.pdf` 抽取文本层；扫描版、加密 PDF 返回 `E_PDF`。PDF 解析在 `catch_unwind` 内，坏文件不会让 MCP 进程退出。
- DOCX/PDF 正文直接由 `fs_read` 读取；只有图片、旧版 `.doc`、压缩包等不支持的二进制才回退宿主内置工具。
- >32 MB 文本文件走流式路径，必须提供连续 `start`/`end`；默认 `scan=window` 只扫描到区间末尾，再读一行判断是否还有内容（`more`），不扫全文件，因此头部省略 hash 与总行数。
- 窗口头固定标注“窗口扫描（未全扫）”；需要全文指纹或精确总行数时用 `scan=full`（全扫，耗时随文件增大）或 `fs_stat detail=hash`。
- 窗口续读尾注分两种：预算在区间内截断时给下一行与原 `end`；区间已全部输出但文件还有内容时给同宽下一窗口（`start=区间末尾+1`），照抄即可重放；区间已到文件末尾时不给续读。
- 窗口模式的 `E_RANGE` 不会伪造总行数，只说明“未全扫”并提示改用 `scan=full` 或先 `fs_grep` 定位。
- 未显式设置 `budget` 且指定了 `end` 或 `ranges` 时，按请求行数自动放宽字节预算，最多 64KB；显式 `budget` 仍以显式值为准。
- 超大 UTF-16 文件和超大文件多区间暂不支持。
- >240 字符的默认行会被截断并标注剩余字符数；需要精确原文时设置 `max_line=0`。尾注「最长截断行约 N 字节，重读该行需 max_line=0 且 budget≈M」按本响应最长截断行计算，配合该行的 `start`/`end` 可直接重读；这是单行成本，不是全文成本。
- 未知顶层字段、负数/浮点 integer 及 `paths` 非字符串元素均返回 `E_BAD_ARGS`，不会静默回退默认行为。

## fs_edit

按原文精确替换或按正则替换，支持同文件多处和跨文件批量。

### 参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | string | 单文件路径；与 `files` 二选一 |
| `edits` | array | 每项二选一：`{old,new}` 字面量，或 `{pattern,replacement}` 正则（引用规则见下）；都可带 `all`/`start`/`end` |
| `diff` | boolean | 附带被替换的原文/新文片段（`@@ 行号` + `-原文`/`+新文`）；默认关闭，改结构后自查用 |
| `files` | array | `[{path, edits, expect_hash?, normalize_eol?}]`，最多 50 个 |
| `dry_run` | boolean | 只预检，不落盘 |
| `expect_hash` | string | 单文件并发保护 |
| `normalize_eol` | boolean | 允许将混合换行归一为主换行风格（多数行使用的风格，平局取 LF） |

`edits` 每项：

| 字段 | 说明 |
|---|---|
| `old` | 原文片段，必须唯一，除非 `all=true` |
| `new` | 替换文本；删除必须显式写 `""`（漏写会被拒绝，不会静默删除） |
| `pattern` | 正则模式；不知道确切原文时用它，省掉为抄原文而做的一次读取 |
| `replacement` | 正则替换内容，捕获组引用写法见下表 |
| `all` | 替换全部匹配 |

同一文件的多个 `edits` 按顺序链式应用：后一个 `old` 匹配的是前一个 `new` 写入后的文本，不是原文。要基于原文匹配就把彼此独立的改动放一起，别让前一处改掉后一处的锚点。

`replacement` 的捕获组引用：

| 写法 | 含义 |
|---|---|
| `$1` / `${1}` | 第 1 个捕获组；组号必须真实存在 |
| `$name` / `${name}` | 命名组（如 `(?P<name>...)`）；名字必须真实存在 |
| `$$` | 字面 `$` |

组号后紧跟字母、数字或下划线时，正则会把它当成组名：`$1_x` 等于找名为 `1_x` 的组（不存在），展开结果为空。这种写法必须写成 `${1}_x`。未知引用、超界组号、未闭合的 `${` 一律返回 `E_BAD_REPLACEMENT` 并指出第几处，不会静默把内容替换成空串。

### 成功输出

```text
ok 3 处修改 (+8 -3) @ 12,40-52,88  /d/repo/a.rs  hash=7b8c...
```

批量：

```text
ok 2 个文件 4 处修改 (+5 -1)
/d/repo/a.rs @ 12,40 hash=...
/d/repo/b.rs @ 8 hash=...
```

### 行为

- 匹配前统一 LF，写回按原文件 EOL 还原。
- 保留原编码和 BOM。
- 所有文件先预检，再开始写入。
- 批量写入不是跨文件事务；中途失败返回 `E_BATCH_PARTIAL`。
- 编辑期间持有跨进程写锁。
- `E_AMBIGUOUS` 返回出现行号，命中行行尾标 `← 列 N`（不插入正文）；`E_NO_MATCH` 返回最接近的 5 行，可直接取其中一行作为 `old` 重试。
- 只知道文本形状、不知道确切原文时用 `pattern`/`replacement`，不必先 `fs_read` 抄原文；`old/new` 与 `pattern/replacement` 二选一。
- `pattern` 可匹配空位置（`^`、`$`、`a*`、`.*`、`\b`）时直接拒绝：那会把每个空位置都替换一遍；与 `fs_grep` 使用同一守卫。
- 结构调整后用 `diff=true` 自查 `@@ 行号` / `-原文` / `+新文`，省掉一次全文回读。

## fs_write

新建文件或整体覆盖。

### 参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | string | 目标路径 |
| `content` | string | 完整内容 |
| `expect_hash` | string | 目标已存在时的并发保护 |
| `normalize_eol` | boolean | 新文件或原文件为混合换行时允许归一为主换行风格（多数行使用的风格，平局取 LF） |
| `dry_run` | boolean | 只做路径/编码/换行/hash 预检，不创建也不覆盖文件 |

### 行为

- 自动创建父目录。
- 临时文件 + fsync + 原子替换。
- 已有文件沿用原编码、BOM 和稳定换行风格。
- 混合内容会归一到已有文件的换行风格。
- 无法用原编码表示新字符时返回 `E_ENCODING_LOSS`。
- 写入期间持有跨进程写锁。
- 目标为 `.docx` 时生成最小 DOCX 包：内容按行转成段落，整文件重建；不保留复杂版式、图片和批注。DOCX 不支持 `fs_edit` 精确替换。
- 目标为 `.pdf` 时返回 `E_PDF`；PDF 只读，不支持写入。

### 成功输出

```text
ok 写入 /d/repo/new.rs 2.4K 80行 hash=...
ok dry_run: /d/repo/new.rs 2.4K 80行 hash=...（将新建文件，未写入）
```

局部修改不要使用本工具，使用 `fs_edit`。

## fs_glob

按文件名查找，尊重 `.gitignore`。

### 参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | string | 搜索根，默认当前目录；也可以是单个文件 |
| `pattern` | string | glob，如 `**/*.rs`；多个用逗号分隔；支持花括号分组，不支持 `|` |
| `dirs` | boolean | 是否包含目录 |
| `detail` | boolean | 是否附大小和修改时间 |
| `limit` | integer | 最多返回条数，默认 200，必须大于 0 |
| `offset` | integer | 跳过前 N 个匹配条目，用于续页 |
| `time_budget_ms` | integer | 目录遍历时间预算，默认 5000 毫秒；`0` 表示立刻返回 |
| `no_ignore` | boolean | 忽略 `.gitignore` 与 `node_modules`/`target` 等默认跳过项；查依赖源码或构建产物时用 |
| `budget` | integer | 响应字节上限，默认 16384 |
| `map` | boolean | 输出 repo map：按符号被引用程度、入口点和 focus 排序的文件与符号，一次调用回答「先看哪些文件」；与 `dirs`/`detail` 互斥 |
| `focus` | string | `map=true` 时的关注词，空格分隔；文件名或符号命中会加权 |
| `max_files` | integer | `map=true` 时最多扫描的文件数，默认 2000 |

### 输出

默认只给路径：

```text
src/main.rs
src/tools.rs
```

还存在后续匹配或预算截断时：

```text
… next_offset=200
```

`next_offset` 按完整输出的匹配条目计数；用 `offset` 重放不会重复。只有真实观察到额外条目才返回续页，恰好等于 `limit` 不会虚报。预算不足以输出一个完整条目时返回 `E_BUDGET`，不返回半路径。


达到 `limit` 后，为确认“是否还有下一页”最多只探测 1024 个后续原始目录项（避免大仓库里把即时返回拖到时间预算上限）。探测到下一个匹配才给 `next_offset`；上限耗尽仍未发现时说明“达到 limit，后续未探测完”，不给 `next_offset`，也不会把它冒充成末页或超时。

`offset` 超出匹配总数，或单文件根的 `offset>0` 时，空页会说明“本页无结果：offset=N 已跳过 M 个匹配条目”，不会报“无匹配”。

`detail=true` 时（文件不带前缀，目录带 `d `）：

```text
8.2K 11-05 17:19 src/main.rs
d 4.0K 11-05 17:10 src/
```

`map=true` 时（repo map）：

```text
/d/repo/src/paths.rs  符号 14 · 被引用 51 处
  16|pub struct FsPath {
  21|impl FsPath {
  … 还有 9 个符号
```

扫描受 `max_files` 与 `time_budget_ms` 限制，超限会在尾注标注；数据文件与 >256 KB 文件跳过。

## fs_grep

按内容搜索，支持四种结果模式、分页、并行扫描和 DOCX/PDF 正文。

### 参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `pattern` | string | Rust 正则；JSON 字符串里反斜杠需双写 |
| `path` | string | 搜索根或单个文件，默认当前目录 |
| `glob` | string | 只搜索匹配文件，如 `**/*.ts` |
| `ignore_case` | boolean | 忽略大小写 |
| `output` | string | `files`、`count`、`matches`、`snippets`；默认 `matches` |
| `context` | integer | 上下文行数，最多 5；snippets 默认 2 |
| `limit` | integer | 本页上限：`files` 按文件，`matches`/`snippets` 按命中；`count` 省略时完整统计，显式设置时按命中 |
| `max_per_file` | integer | 每文件最多显示命中数 |
| `max_line` | integer | 命中行最多显示字符数，默认 240（与 `fs_read` 一致）；`0` 表示不截断，一次拿到完整长行，省掉再 `fs_read` 一轮 |
| `offset` | integer | `files` 跳过前 N 个匹配文件；其他模式跳过前 N 个命中 |
| `parallel` | boolean | 并行扫描；省略时自动按仓库规模选择：小仓库串行，大仓库并行；`true` 强制并行，`false` 强制串行；输出与串行一致 |
| `budget` | integer | 响应字节上限，默认 16384 |
| `time_budget_ms` | integer | 文件与目录遍历总时间预算，默认 5000 |
| `max_file_size` | integer | 只搜索不超过该字节数的文件，默认 8388608（8 MiB）；`0` 表示不限制 |
| `no_ignore` | boolean | 忽略 `.gitignore` 与 `node_modules`/`target` 等默认跳过项；搜依赖源码时用 |

### 模式

```text
files    每个文件只给路径，limit/offset 按文件计数
count    路径:真实行命中数，默认完整统计
matches  行号:内容
snippets 默认带 2 行上下文
```

`.docx` 会先抽取 `word/document.xml` 正文再匹配，`.pdf` 先抽取文本层；行号对应抽取后的正文行。旧版 `.doc`、图片和压缩包仍跳过。

超过 `max_file_size`（默认 8 MiB，`0` 表示不限制）的文件不参与搜索；尾注会报告跳过数量、当前上限、默认值、最大体积和调法，避免把“没搜到”误当成“不存在”。

### 输出示例

```text
src/server.rs
12:func NewServer(cfg Config) *Server {
…

… next_offset=100
```

### 分页

- `files` 每个文件只保留首次命中，高密度首文件不会挤掉后续文件；`count` 只保存每文件聚合数，不物化逐命中正文。
- `max_per_file` 对 `files`、`count`、`matches`、`snippets` 一律生效，且在模式分支之前执行：`files` 配合 `max_per_file=0` 会明确说明“无可见命中”，`count` 配合 `max_per_file=1` 每文件只给 1 并在尾注给出省略数量。
- `count` 显式设置 `limit` 或超时时会标记结果不完整；默认不受 100 条命中上限影响。`offset>0` 时每文件数字标为“本页可见”，不能读成文件总数。
- 截断时使用返回的 `next_offset`，不要手动猜测。
- `files` 的 `offset` 超出匹配文件数时，空页用“已跳过 M 个匹配文件”说明，不会伪装成“无命中”。
- `offset` 超出匹配总数会明确提示，不会伪装成“无命中”。
- 每文件命中被 `max_per_file` 省略时，尾注会给出省略数量。
- 目录遍历超时（包括 glob 过滤后一次命中都没扫描到）会返回 `E_TIMEOUT`，不会报“无命中”。
- 并行模式与串行模式输出一致，但为了保证顺序可能多扫描当前波次。
- 时间预算覆盖目录遍历、文件读取和逐行匹配。

## fs_stat

查看路径元信息。

### 参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | string | 单个路径 |
| `paths` | string[] | 多个路径，最多 50 个 |
| `detail` | string | `meta`、`hash`、`full`、`server`；默认 full。`server` 一条调用确认服务端版本与工具数，升级后自检用 |

### 模式

| 模式 | 读取内容 | 输出 |
|---|---|---|
| `meta` | 不读 | 路径、类型、大小、时间、只读 |
| `hash` | 读一次 | 元信息、编码、换行、hash |
| `full` | 读一次 | 元信息、编码、换行、行数、hash |
| `server` | 不读 | `fsops 0.6.0 tools=8`——一条调用确认服务端版本与工具数，自检用 |

二进制文件输出 `binary` 标记和 hash，不做文本解码。

多文件部分失败时首行给出 `ok stat N 项：X 成功，Y 失败`，后面仍逐项输出；MCP 层 `isError` 仍为 true（保守），调用方可从首行判断还有多少内容可用。

DOCX 的 `hash`/`full` 会抽取正文后报告 `docx LF` 和正文行数；PDF 报告 `pdf LF`。不把压缩包或 PDF 二进制当文本解码。

### 输出示例

路径一律用双引号包裹，含空格的路径也能稳定切出；其后字段以空格分隔，`hash=` 恒在末尾。

```text
"/d/repo/a.rs" file 8.2K 2026-11-05 17:19 utf-8 LF rw 240行 hash=1fc9f68801e1a113
```

目录：

```text
"/d/repo" dir 0B 2026-11-05 17:19
```

## fs_exec

执行程序。`program` + `args` 数组，**不经过 shell**：没有引号、`$`、反引号、`2>&1`、`ErrorRecord`、`$LASTEXITCODE` 问题。

### 参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `program` | string | 可执行文件，走 PATH；启动新任务时必填，只轮询/终止 `job` 时可省略 |
| `args` | string[] | 参数数组，每个参数独立 |
| `cwd` | string | 工作目录；与文件工具同一套路径解析，`/d/repo`、`D:/repo`、相对路径均可；不存在时返回 `E_BAD_ARGS` |
| `timeout_ms` | integer | 默认 120000，最大 600000；超时结束整个进程树 |
| `stdin` | string | 标准输入 |
| `env` | object | 追加/覆盖环境变量 |
| `shell` | boolean | 显式走 `cmd /c`，只在需要管道/重定向时用 |
| `max_output` | integer | 每条流最多保留字节，默认 32768 |
| `check` | boolean | 非零退出按 `E_EXIT` 错误返回；默认 false，非零仍是 ok |
| `background` | boolean | 会话内后台任务：立即返回 job id；进程随 MCP 会话结束，不适用长驻服务 |
| `job` | integer | 轮询/终止后台任务：传启动时返回的 job id |
| `list` | boolean | 列出当前会话的全部后台任务（id/pid/状态/时长） |
| `wait_ms` | integer | 配合 `job`：最多等待 N 毫秒直到任务退出再返回（上限 60000）；超时仍运行则返回增量输出 |
| `kill` | boolean | 配合 `job`：结束该任务的整个进程树 |

### 输出

```text
ok exit=0 6543ms stdout=1234B stderr=0B
--- stdout ---
...
--- stderr ---
...
```

- **非零退出不是错误**：`ok exit=1`，测试失败是正常结果；显式要错误语义时传 `check=true`，返回 `E_EXIT code=1`
- 超时：`E_TIMEOUT program=... 超过 ...ms，已结束进程树`
- 找不到程序：`E_NOT_FOUND ...`
- 输出编码自动识别（UTF-8 / GBK）

### 后台任务

```json
{"program":"npm","args":["run","dev"],"cwd":"D:/repo","background":true}
```

```text
ok job=1 pid=1234 会话内后台任务已启动（fs_exec job=1 轮询，list=true 列出全部，kill=true 结束）
```

轮询只返回上次之后的**新增**输出；`job` 加 `wait_ms=5000` 可最多等 5 秒直到任务退出，短命令一次调用拿全结果；`kill=true` 结束整个进程树；`list=true` 列出全部任务，丢了 job id 时用它自救。后台任务只在长驻的 MCP 服务进程内有效，`fsops call` 一次性进程会拒绝；**进程随 MCP 会话结束**（宿主重启即终止），不适合真正的长驻服务。

## fs_file

文件管理，按 `op` 分派。

| op | 参数 | 说明 |
|---|---|---|
| `copy` | `src`,`dst`,`overwrite` | 文件或目录递归 |
| `move` | `src`,`dst`,`overwrite` | 同盘 rename，跨盘 copy + delete |
| `remove` | `path`,`recursive`,`confirm` | **`confirm=true` 必填**；拒绝盘符根目录 |
| `mkdir` | `path` | 递归创建，已存在算成功 |
| `convert` | `path`,`encoding`,`eol` | UTF-8 / UTF-8 BOM / GBK / GB18030 / UTF-16 与 CRLF / LF 转换 |
| `archive` | `src`,`dst`,`overwrite` | 把文件或目录打包成 zip |
| `extract` | `src`,`dst`,`overwrite` | 解压 zip；拒绝 zip-slip 路径 |

所有 op 支持 `dry_run=true`。

```text
ok copy /d/repo/a.txt -> /d/repo/b.txt（1 个文件，22B）
ok move /d/repo/a.txt -> /d/repo/b.txt（1 个文件，22B）
ok remove /d/repo/out
```

## 错误码

以 `E_` 开头的行表示错误，MCP 响应同时设置 `isError=true`。每条错误都给出可执行的下一步。

### 参数与调用

| 错误码 | 含义 | 下一步 |
|---|---|---|
| `E_BAD_ARGS` | 参数缺失、类型错误或越界 | 按提示修正对应参数 |
| `E_BAD_PATH` | 路径无法解析 | 用 `fs_glob` 确认真实路径 |
| `E_BAD_GLOB` | glob 模式非法 | 用逗号分隔多个模式，如 `*.rs,*.ts` |
| `E_BAD_REGEX` | 正则非法，或用了 glob 写法 | 改成正则（`*.txt` → `.*\.txt`），或改用 `fs_glob` |
| `E_BAD_EDIT` | `edits` 结构错误（缺 `old`/`new`） | 每项必须同时给出 `old` 与 `new` |
| `E_UNKNOWN_TOOL` | 工具名不存在 | 用 `tools/list` 查看可用工具 |
| `E_UNKNOWN_CMD` | CLI 子命令不存在 | 用 `fsops help` 查看 |

### 读取

| 错误码 | 含义 | 下一步 |
|---|---|---|
| `E_READ` | 文件读取失败（不存在或无权限） | 不存在时列出同目录最相似的 3 个条目；否则检查权限与占用 |
| `E_NOT_FOUND` | 路径不存在 | 用 `fs_glob` 定位 |
| `E_IS_DIR` | 目标是目录而非文件 | 读目录用 `fs_glob` |
| `E_BINARY` | 二进制文件 | 不支持文本读取 |
| `E_RANGE` | 行区间超出文件范围 | `scan=full` 时提示实际总行数；`window` 提示未全扫并建议 `scan=full` 或先 `fs_grep` 定位 |
| `E_LINE_TOO_LONG` | 单行过长，当前 budget 放不下 | 设 `max_line=0` 并把 `budget` 提到提示给出的数值 |
| `E_BUDGET` | 预算不足以输出有意义的片段 | 按提示增大 `budget` |
| `E_TOO_LARGE` | 文件超过 32MB，一次只支持一个连续区间 | 先用 `fs_grep` 定位行号，再用 `start`/`end` 读该区间 |
| `E_TOO_LARGE_UTF16` | 超大文件是 UTF-16 编码，无法流式读取 | 先转存为 UTF-8 再读 |
| `E_TIMEOUT` | 搜索超出时间预算 | 缩小范围或增大 `time_budget_ms` |
| `E_PDF` | PDF 无文本层（扫描版/加密） | 只能人工处理 |
| `E_DOCX` | DOCX 不支持精确替换 | 用 `fs_write` 整体重建 |

### 写入与编辑

| 错误码 | 含义 | 下一步 |
|---|---|---|
| `E_WRITE` | 写入失败 | 检查路径与权限 |
| `E_OPEN` | 打开文件失败 | 检查是否被占用 |
| `E_MKDIR` | 创建目录失败 | 检查父目录权限 |
| `E_RENAME` | 原子替换失败 | 常见原因是目标只读或被杀软锁定 |
| `E_READONLY` | 目标文件只读 | 提示里给出 `Set-ItemProperty` 命令 |
| `E_LOCKED` | 文件被其他进程占用 | 稍后重试 |
| `E_LOCK` | 无法取得跨进程写锁 | 稍后重试 |
| `E_STALE` | 文件已被修改，`expect_hash` 不匹配 | 重新 `fs_read` 后用新 hash |
| `E_NO_MATCH` | 找不到目标文本 | 提示里给出最接近的 5 行，可直接用作 `old` 重试 |
| `E_AMBIGUOUS` | 匹配到多个位置 | 加更多上下文、设 `all=true`，或用 `start`/`end` 限定行范围 |
| `E_MIXED_EOL` | 文件混合换行 | 显式设 `normalize_eol=true` 归一为主换行风格（多数行使用的风格，平局取 LF） |
| `E_ENCODING_LOSS` | 新文本含原编码无法表示的字符 | 提示里给出码位与行号；替换这些字符或改用 UTF-8 |
| `E_BATCH` | 批量写入参数错误 | 检查 `files` 结构 |
| `E_BATCH_PARTIAL` | 批量写入中途失败，部分文件已写入 | 提示里说明已写入几个；重试剩余文件 |
| `E_ENCODING` | 编码识别失败 | 显式转存为 UTF-8 或 GBK |
| `E_SYNC` | 写入后同步失败 | 检查磁盘状态 |

### 文件管理与执行

| 错误码 | 含义 | 下一步 |
|---|---|---|
| `E_CONFIRM_REQUIRED` | `fs_file remove` 未带 `confirm=true` | 确认删除不可恢复后显式传 `confirm=true` |
| `E_EXISTS` | 目标已存在且未允许覆盖 | 传 `overwrite=true` 或换目标 |
| `E_IO` | 创建、复制、删除或读目录失败 | 检查权限、占用与只读属性 |
| `E_ZIP` | 压缩/解压失败、条目过多或 zip-slip | 确认 zip 完好；解压路径必须在目标目录内 |
| `E_NO_JOB` | 后台任务不在当前会话内 | 在长驻 MCP 会话里启动；`fsops call` 每次都是新进程 |
| `E_JOB_LIMIT` | 后台任务已达 16 个 | 先 `kill` 不需要的任务 |
| `E_JOB` | 后台任务表不可用 | 重启 MCP 服务 |
| `E_BAD_REPLACEMENT` | 正则替换引用了不存在的捕获组 | 检查组号/命名组；`$1_x` 要写成 `${1}_x` |
| `E_INTERNAL` | 工具执行崩溃（MCP error 响应） | 缩小请求范围后重试；持续出现请报 issue |
| `E_EXIT` | `fs_exec` 非零退出且 `check=true` | 按输出判断失败原因；重试或修正参数 |

### 集成与诊断

| 错误码 | 含义 | 下一步 |
|---|---|---|
| `E_INTEGRATE` | 规则写入失败 | 检查目标文件权限 |
| `E_RULE_BLOCK` | 受管块标记损坏 | 用 `integrate --remove` 后重装 |
| `E_RULE_CHECK` | 规则检查未通过 | 按 `doctor` 输出修正 |
| `E_HARDEN` | hook 安装失败 | 检查 Claude Code 配置目录权限 |
| `E_DOCTOR` | 环境检查发现问题 | 按报告逐项修复 |
| `E_SETTINGS` | 宿主配置文件格式错误 | 修正 JSON 后重试 |
| `E_REMOVE` | 卸载时删除失败 | 检查文件占用 |
| `E_UPGRADE` | 自更新失败（网络、SHA-256 不匹配、目录不可写） | 校验失败不会替换任何文件；按提示重试或改用一行安装脚本 |

## MCP 协议

- stdio，换行分隔 JSON-RPC 2.0
- 方法：`initialize`、`tools/list`、`tools/call`、`ping`
- `fsops mcp --jobs N`：tools/call 用固定线程池并发处理，默认 4；`0/1` 为单工作线程串行——读线程仍可就地应答控制类请求，`background`/`wait_ms` 不会把后续请求卡死
- 工具返回：`{"content":[{"type":"text","text":"..."}],"isError":false}`
- 日志不写入 stdout

## CLI

```bash
fsops mcp                                   # 以 MCP stdio 服务运行
fsops upgrade [--check] [--force]           # 自更新：查最新 Release、SHA-256 校验后替换
fsops read <path> [--start N] [--end N] [--budget N]
fsops grep <pattern> [--path DIR] [--glob G] [--context N] [--ignore-case]
fsops glob [pattern] [--path DIR] [--dirs] [--limit N]
fsops stat <path...>
fsops call <tool> '<json>'                  # JSON 作为参数
fsops call <tool> -                          # JSON 从标准输入读（大参数用这个）
fsops install <claude|hermes|codex|json>
fsops integrate --rules [--target ...]      # 写入 fsops 软规则块
fsops doctor [--json]                       # 检查规则与宿主接入
fsops harden claude [--path DIR|--user]     # Claude Code PreToolUse 接管
fsops hook claude                           # hook 处理器（由 harden 安装）
fsops version
```

> Windows 单个进程参数上限约 32 KB。`fs_write` 的大段 `content` 或批量 `edits` 请用
> `fsops call <tool> -` 从标准输入传 JSON；DSH 插件也走这条路径。
