# 使用指南

本文覆盖安装、宿主接入、Agent 工作流、错误处理和升级卸载。完整参数见 [工具参考](工具参考.md)。

## 1. 适用场景

fsops 适合：

- Windows 10/11 上的编码 Agent
- 中文路径、GBK、UTF-16、BOM、CRLF 混用的项目
- 需要减少工具输出 token 和多轮读取的代码仓库
- 需要多个 Agent 进程安全修改同一批文件的场景
- 同时使用 Claude Code、Codex、Cursor、Cline、Hermes 或自研 harness

不适合：

- 非文本且非 DOCX/PDF 的文件处理
- 图片、旧版 `.doc` 内容抽取
- 需要 Windows 原生管理能力（服务、注册表、ACL）的批量操作
- 需要强沙箱的多租户环境

## 2. 安装

### 一行安装（推荐）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/install.ps1')).TrimStart([char]0xFEFF)))"
```

> 为什么不用 `irm … | iex`：Windows PowerShell 5.1 的 `irm` 会把 UTF-8 BOM 解成 `ï»¿` 三个字符，使 `[CmdletBinding()]` 不再是脚本首语句，`iex` 会报 `UnexpectedAttribute` / `param` 意外标记。上面的命令用 `Net.WebClient` 取原始字节、按 UTF-8 解码并去掉 BOM，再交给 `[scriptblock]::Create` 执行，5.1 与 PowerShell 7 都可用；需要传参数时在末尾追加（如 `-Client none -NoPath`）。

脚本会完成：

1. 解析最新 Release
2. 下载 Windows x64 二进制和 SHA-256
3. 校验哈希
4. 安装到 `%LOCALAPPDATA%\fsops`
5. 加入用户 `PATH`
6. 自动注册检测到的 Claude Code、Hermes 和 Codex

常用选项：

```powershell
# 只安装，不注册任何宿主，不修改 PATH
& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/install.ps1')).TrimStart([char]0xFEFF))) -Client none -NoPath

# 指定版本和目录
& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/install.ps1')).TrimStart([char]0xFEFF))) -Version v0.7.0 -InstallDir "$env:LOCALAPPDATA\fsops"

# 只检查资产存在，不下载
.\scripts\install.ps1 -DryRun

# 只注册某一个宿主
.\scripts\install.ps1 -Client claude
```

### 手动安装

1. 打开 [最新 Release](https://github.com/tokenis2023/agent-ops/releases/latest)。
2. 下载 `fsops-v*-windows-x86_64.exe` 和对应 `.sha256`。
3. 重命名为 `fsops.exe`，放入一个固定目录并加入用户 `PATH`。
4. 校验 SHA-256。

```powershell
$target = "$env:LOCALAPPDATA\fsops"
New-Item -ItemType Directory -Force $target | Out-Null
Move-Item .\fsops.exe $target -Force

$userPath = [Environment]::GetEnvironmentVariable("Path", "User")
if ($userPath -notlike "*$target*") {
  [Environment]::SetEnvironmentVariable("Path", "$userPath;$target", "User")
}

Get-FileHash "$target\fsops.exe" -Algorithm SHA256
fsops version
```

新终端生效后，`fsops version` 应输出版本号。安装后在项目根目录执行 `fsops integrate --rules`，让 Agent 优先选择 fsops。

> Windows SmartScreen 可能提示未知发布者，因为当前二进制未做代码签名。请先核对 Release 的 SHA-256。

### 从源码构建

仅用于开发或自行分发：

```bash
cargo build --release
```

Windows GNU 工具链需要 MinGW；MSVC 工具链使用系统链接器。

## 3. 接入宿主

### Claude Code

```bash
claude mcp add fsops -- fsops mcp
claude mcp list
```

需要让内置文件工具真正让路时，安装 PreToolUse 硬接管：

```bash
fsops harden claude
fsops harden claude --check
```

默认写项目 `.claude/settings.json`；`--user` 写用户级配置。图片、旧版 `.doc`、压缩包等二进制仍放行内置 `Read`。

### Hermes

```bash
hermes mcp add fsops --command fsops --args mcp
hermes mcp test fsops
```

Hermes 把 MCP 工具放进 on-demand（deferred）目录，而内置 `read_file` / `patch` / `terminal` **始终可见**，所以模型默认会先用内置工具——注册成功不等于会被使用。

实测结论：

- `tools.tool_search.defer: []` **不能**让 MCP 工具变 eager。Hermes 把所有 `mcp-*` toolset 都当作可延迟，这个列表只覆盖核心/插件工具；改了不报错也不生效。
- 想让 fsops 真被优先使用，只有两条路：

1. **专用 profile（真强制）**：关掉文件类内置工具，保留 shell。

   ```bash
   hermes tools disable file
   hermes tools disable coding
   ```

   工具集变更在**新会话**生效（`/reset` 后验证）。粒度粗，但是真实可见性约束。

2. **CLI 兜底**：直接用 `fsops read/grep/glob/stat/call`，不依赖 MCP 可见性。

升级 fsops 后，运行中的宿主仍持有旧进程与旧 schema；执行 `/reload-mcp` 或重启 Hermes 后，新二进制与 schema 才会加载。

确认是否**真的在用**（而不是只注册了）：

```bash
sqlite3 ~/.hermes/state.db "select count(*) from messages where tool_name like 'mcp__fsops__%'"
```

大于 0 才算调用过；`hermes mcp test fsops` 只证明能握手和列出工具。

### 多个 Agent 同时使用

fsops 的写锁是 **按文件** 的跨进程命名互斥量（`Local\\fsops-write-<hash>`，路径小写后取 hash），读-改-写全在锁内，`expect_hash` 也在锁内校验。实测结果：

| 场景 | 实测 |
|---|---|
| 20 个进程并行改同一文件的不同行 | 20/20 成功，0.36s |
| 8 个进程同时改同一行 | 2 成 6 败，失败方 `E_NO_MATCH`，文件结构未损坏 |
| 10 个进程同时 `fs_write` 整文件 | 10/10 成功，最终内容是某一个写者的完整版本，无交错 |
| 同一文件的 `/c/x`、`C:/x`、`C:\\x`、大写写法 | 映射到同一把锁，互斥生效 |

结论与建议：

- **改不同文件/不同行：安全**，无需额外协调。
- **改同一行：会有一方失败**，失败方拿到 `E_NO_MATCH`。让每个 agent 先 `fs_read` 再带 `expect_hash` 写入，失败方会得到语义更明确的 `E_STALE`（“文件已变化”）而不是“找不到文本”。
- **读操作不加锁**：写是临时文件 + 原子替换，读者只会看到旧版本或新版本，不会读到半截文件。
- **锁超时 3000ms**：拿不到锁返回 `E_LOCKED`，重试即可。正常并发下很难触发（实测 20 进程无超时）。
- **单宿主是串行的**：一个 MCP 服务进程一次处理一个请求。多个 teammate 共用一个宿主时，一个耗时的 `fs_grep` 会让其他人的调用排队；想避开就给每个 teammate 独立宿主进程。
- **锁的作用域限于同一登录会话**（`Local\\` 命名空间）。跨用户、跨服务、或以不同权限运行的两个 fsops 不互斥。
- **符号链接/junction 不归一**：锁键是路径字符串，同一文件通过链接和真实路径访问会被当成两个文件。并行写时请用同一写法。

### Cursor / Windsurf / Cline

在宿主的 MCP JSON 配置中加入：

```json
{
  "mcpServers": {
    "fsops": {
      "command": "fsops",
      "args": ["mcp"]
    }
  }
}
```

### Codex

在 `~/.codex/config.toml` 中加入：

```toml
[mcp_servers.fsops]
command = "fsops"
args = ["mcp"]
```

### DeepSeek Harness（插件形态）

仓库根是一个标准 DSH bundle。打开侧栏 **插件 → 添加插件 → 安装第三方插件**，粘贴仓库地址；生产环境建议固定 tag/commit：

```text
github:tokenis2023/agent-ops#v0.7.0
```

安装后默认启用，提供 8 个 `fs_*` 工具，与 MCP 形态同名、同错误码。插件**复用一条长驻 `fsops mcp` 会话**（换行分隔 JSON-RPC、按 id 匹配响应），不是每次调用新起进程：release 构建实测单次工具调用 **~33ms → 0.3–0.6ms**（debug 构建复跑约 0.5–0.8ms）。会话不可用（spawn 失败、进程退出、初始化失败）时自动退回一次性 `fsops call`，功能不降级；想强制走一次性调用可配 `mcp: false`。取消（abort）单个进行中的写/执行请求会结束长驻会话以阻止后台继续执行，下一次调用自动重建。参数集合与 MCP 形态基本一致；唯一差异是插件形态**不提供** `fs_exec` 的后台任务参数（`background`/`job`/`list`/`wait_ms`/`kill`）：schema 不声明，运行时也会显式拒绝并提示改用 MCP 形态。

- 二进制优先用 `%LOCALAPPDATA%\fsops` 或 PATH 上已有的 `fsops.exe`；都没有时按 bundle 版本从
  GitHub Release 下载并校验 SHA-256（该版本还没发 Release 时回退到 latest），缓存到
  `%LOCALAPPDATA%\fsops-dsh\<版本>`。
- 离线环境先跑 `install.ps1`，或在 profile 的 `cordis.patch.yml` 里按 `fsops-tools` 覆盖 `config.binary`。
- bundle 声明 `dsh.bundle.platforms: ["win32"]`，非 Windows 宿主不会展示；`engines.dsh` 声明兼容 `>=0.2.2-rc.1`。
- 安装后建议自检：会话里 `fs_stat detail=server` 应返回与插件同版本的 `fsops x.y.z tools=8`；不符会报 `E_VERSION`。
- **安全边界**：DSH 插件是 Host 代码，Harness 的 fs 沙箱与审批只约束内置文件工具和受限 shell，**不覆盖 `fs_*`**；需要强制隔离请改用 MCP 形态并配合宿主沙箱，或只在可信工作区启用。
- **错误分层**：宿主会先按 schema 校验参数（type/enum），失败是英文 `invalid arguments: ...`；通过后才进入内核返回中文 `E_*`。
- 同时装了 MCP 形态时两套工具会并存（`fs_*` 与 `mcp__fsops__fs_*`），建议只保留一种。

#### 从源码本地部署（开发用）

插件 JS 与 fsops.exe **必须同版本**：工具定义从 `fsops schema` 生成，只换插件不换内核时，
新参数（`fs_write.files`、`fs_grep.expand`）会被旧内核拒绝成 `E_BAD_ARGS`。

```powershell
# 1. 构建
cargo build --release
node scripts/gen_dsh_specs.mjs --exe target/release/fsops.exe

# 2. 同步插件（profile 的 node_modules）
$pkg = Join-Path $env:USERPROFILE '.dsh\profiles\desktop\node_modules\@tokenis2023\fsops'
Copy-Item dsh\*.js "$pkg\dsh\" -Force
Copy-Item package.json, cordis.patch.yml, icon.svg, locale\*.json $pkg -Force
Copy-Item docs\* "$pkg\docs\" -Recurse -Force

# 3. 完全退出 DeepSeek Harness 后，再换内核（运行中 exe 被长驻会话占用会 EBUSY）
.\scripts\deploy-local.ps1
```

正式发布走 tag + Release（插件 pin 到 tag/commit，二进制由 Release 提供），本地脚本只用于开发验证。

### 仅支持 shell 的 Agent

直接调用 CLI：

```bash
fsops read /d/repo/src/main.rs --start 40 --end 80
fsops grep "func NewServer" --path /d/repo --glob "**/*.go"
fsops glob "**/*.ts" --path /d/repo/web
fsops stat src/lib.rs
fsops call fs_exec '{"program":"cargo","args":["test"],"cwd":"D:/repo"}'
fsops call fs_file '{"op":"copy","src":"a.txt","dst":"b.txt"}'
fsops call fs_edit '{"path":"/d/repo/a.txt","edits":[{"old":"a","new":"b"}]}'
# JSON 走标准输入：参数太长（>32 KB）时用这种方式
echo '{"path":"/d/repo/a.txt","content":"..."}' | fsops call fs_write -
```

修改 MCP 配置后，当前会话可能仍使用旧工具列表。执行宿主提供的 `/reload-mcp`，或新开会话/重启宿主。

## 4. 验证接入

1. 确认进程能启动：`fsops version`
2. 确认 MCP 握手：`hermes mcp test fsops` 或宿主对应命令
3. 确认规则已写入：`fsops doctor`
4. 让 Agent 调用一次只读工具，例如 `fs_stat` 或 `fs_glob`；`fs_stat detail=server` 会返回服务端版本与工具数，可直接确认连的是新版
5. 再验证一次 `fs_read` 和 `fs_edit dry_run`

仅看到“连接成功”不够，实际调用成功才算完成接入。

## 5. 推荐的 Agent 规则

在项目根目录执行：

```bash
fsops integrate --rules
```

默认写入 `AGENTS.md` 和 `CLAUDE.md`，并带有可重复更新的受管标记。需要覆盖 Cursor、Windsurf、Cline、Gemini 和 Copilot：

```bash
fsops integrate --rules --target all
```

检查状态：

```bash
fsops integrate --rules --check
fsops doctor
```

规则块只做软引导；要确认宿主是否真的注册了 fsops，用 `fsops doctor`。详细规则见 [AGENTS.md](../AGENTS.md)。

如果宿主把 fsops 放在 deferred 工具目录（例如 Hermes 的 `tool_search`），先让 Agent 执行一次工具发现，或直接使用 `fsops read/grep/glob/stat/call` CLI；不要先用内置 `Read`/`Bash` 试探。

关键点：

- 文件操作优先 fsops
- 构建、测试、git 和包管理用 `fs_exec` 启动；进程、服务、端口仍用系统工具
- 局部修改用 `fs_edit`，不要 `fs_write`
- 多文件修改一次批量提交
- 截断时使用 `next_offset` 或 `ranges`
- `E_STALE`/`E_LOCKED` 不要原样重试

## 6. 标准工作流

### 定位代码

```json
{"pattern": "NewServer", "path": "/d/repo", "glob": "**/*.go", "output": "files"}
```

再取上下文：

```json
{"pattern": "func NewServer", "path": "/d/repo", "glob": "**/*.go", "output": "snippets", "context": 3}
```

最后精读：

```json
{"path": "/d/repo/server.go", "ranges": [[40, 90], [180, 230]]}
```

### 安全修改

1. `fs_read` 获取片段和 `hash`。
2. `fs_edit` 带 `expect_hash`：

```json
{
  "path": "/d/repo/server.go",
  "expect_hash": "1fc9f68801e1a113",
  "edits": [
    {"old": "const timeout = 5", "new": "const timeout = 10"},
    {"old": "return nil", "new": "return ctx.Err()"}
  ]
}
```

3. 根据返回的新 hash 决定是否继续修改。

### 多文件修改

```json
{
  "files": [
    {
      "path": "/d/repo/a.rs",
      "expect_hash": "aaaaaaaaaaaaaaaa",
      "edits": [{"old": "old_a", "new": "new_a"}]
    },
    {
      "path": "/d/repo/b.rs",
      "expect_hash": "bbbbbbbbbbbbbbbb",
      "edits": [{"old": "old_b", "new": "new_b"}]
    }
  ]
}
```

所有文件先预检；任一失败时不会写入任何文件。写入阶段仍不是跨文件事务，失败会返回 `E_BATCH_PARTIAL`。

### 大文件

```json
{"path": "/d/repo/huge.log", "start": 12000, "end": 12080, "budget": 8192}
```

超大 UTF-16 文件和超大文件的多区间 `ranges` 暂不支持。

### 并发修改

- 每个进程写同一文件时持有 3 秒超时的跨进程锁。
- 带 `expect_hash` 时在锁内重新校验内容指纹。
- 其他进程正在写时返回 `E_LOCKED`，不要立即原样重试，先重新读取确认状态。

### 执行命令

用 `fs_exec` 的 `program` + `args` 数组直接启动程序，不经过 shell，引号和 `$` 不会被二次解释：

```json
{"program": "cargo", "args": ["test", "--lib", "tools::"], "cwd": "D:/repo"}
```

- 非零退出不是错误：返回 `ok exit=1`，按输出判断结果；要错误语义时传 `check=true`，非零返回 `E_EXIT code=N`。
- 超时默认 120 秒、上限 600 秒，超时结束整个进程树。注意宿主对单次工具调用通常有更短超时（约 2 分钟），前台长任务会被宿主截断且结果丢失；超过这个时长的构建/测试改用 `background=true`。
- `program` 用 PATH 名或原生绝对路径（`D:/repo/x.exe`）；相对路径不随 `cwd` 解析。
- 输出按 UTF-8 / GBK 自动解码，每条流默认保留 32 KB，可用 `max_output` 调整。
- 需要管道或重定向时才显式传 `shell=true`，此时会回到命令行解析。
- 长驻命令用 `background=true` 启动，记下返回的 job id；之后用 `{"job": 1}` 轮询新增输出，`{"job": 1, "wait_ms": 5000}` 最多等 5 秒直到退出、短命令一次拿全结果，`{"job": 1, "kill": true}` 结束进程树，`{"list": true}` 列出全部任务。它是**会话内**任务：进程随 MCP 会话结束，`fsops call` 一次性进程会拒绝，不适合真正的长驻服务。

### 文件管理

`fs_file` 按 `op` 分派，替代 `Copy-Item` / `Move-Item` / `Remove-Item` / `New-Item` 与压缩解压：

| op | 示例 | 说明 |
|---|---|---|
| `copy` | `{"op":"copy","src":"a","dst":"b","overwrite":true}` | 文件或目录递归 |
| `move` | `{"op":"move","src":"a","dst":"b"}` | 同盘 rename，跨盘复制后删除 |
| `remove` | `{"op":"remove","path":"a","confirm":true}` | 目录需同时 `recursive=true`；拒绝盘符根目录 |
| `mkdir` | `{"op":"mkdir","path":"out/cache"}` | 递归创建，已存在算成功 |
| `convert` | `{"op":"convert","path":"a.txt","encoding":"gbk","eol":"crlf"}` | 编码与换行转换 |
| `archive` | `{"op":"archive","src":"dist","dst":"dist.zip"}` | 打包 zip |
| `extract` | `{"op":"extract","src":"dist.zip","dst":"out"}` | 解压 zip，拒绝 zip-slip |

所有 op 支持 `dry_run=true`；`remove` 不带 `confirm=true` 会返回 `E_CONFIRM_REQUIRED`。

## 7. 错误码

| 错误 | 含义 | 推荐动作 |
|---|---|---|
| `E_READ` | 文件读取失败 | 不存在时会列出同目录候选；否则检查权限、占用 |
| `E_NOT_FOUND` | 路径不存在 | 先用 `fs_glob`/`fs_grep` 定位 |
| `E_IS_DIR` | 目标是目录 | 改读目录下具体文件 |
| `E_BAD_PATH` | 路径无法解析 | 检查盘符/POSIX 写法 |
| `E_BAD_ARGS` | 参数错误 | 按提示补齐或修正 |
| `E_BAD_REGEX` | 正则无效 | 转义特殊字符 |
| `E_BAD_GLOB` | glob 无效 | 使用 `**/*.rs` 形式 |
| `E_AMBIGUOUS` | 匹配不唯一 | 增加上下文或显式 `all=true` |
| `E_NO_MATCH` | 未找到目标 | 从候选行重新取原文 |
| `E_STALE` | 文件已被其他操作修改 | 重新 `fs_read` 后再改 |
| `E_LOCKED` | 其他进程正持有写锁 | 稍后重试并重新校验 hash |
| `E_MIXED_EOL` | 混合换行保护 | 确认后显式 `normalize_eol=true`，会归一到多数行使用的风格（平局取 LF） |
| `E_ENCODING_LOSS` | 目标编码无法表示新字符 | 改用原编码可表示的文本，或显式转换文件 |
| `E_LINE_TOO_LONG` | 单行无法放入预算 | 增大 `budget` 或减小 `max_line` 后分段读 |
| `E_RANGE` | 行区间超出文件 | 用 `fs_stat`/`fs_read` 检查总行数 |
| `E_TOO_LARGE` | 超大文件缺少连续区间 | 指定 `start` 和 `end` |
| `E_TIMEOUT` | 搜索时间预算用尽 | 缩小 path 或加 glob |
| `E_BUDGET` | 输出预算不足 | 增大 budget |
| `E_BATCH` | 批量预检失败 | 按文件路径修正后重试 |
| `E_BATCH_PARTIAL` | 写入阶段部分失败 | 检查已写文件，重新读取剩余文件 |

## 8. 排障

### 升级后工具面仍是旧版

宿主的 MCP 工具面是按连接配置（command/args）缓存的，**fsops 二进制升级不改变配置指纹**，宿主重连时不一定重新 `tools/list`，结果是工具数/描述仍是旧版的，看起来「升了个假的」。

先确认连的是哪一版（不需要重启）：

```json
{"detail": "server"}
```

返回形如 `fsops 0.3.0 tools=8`。若工具数/版本与期望不符：

1. 执行宿主提供的 `/reload-mcp`（Hermes）或新开会话；
2. Hermes 持有 `cache/mcp_schema_cache.json` 的 schema 缓存，重启仍不生效时删除该文件后再重连；
3. 若仍然是旧工具数，检查是否有多个 fsops 安装（`fsops doctor`），或配置里的 `command` 是否指向旧路径。

### 宿主看不到工具

1. 确认命令可执行：`fsops version`
2. 重新握手：`hermes mcp test fsops`
3. 新开会话或 `/reload-mcp`
4. 检查宿主是否禁用了当前目录或 MCP 工具

### 重新构建时提示文件被占用

停止正在持有的 MCP 子进程：

```powershell
Get-Process fsops -ErrorAction SilentlyContinue | Stop-Process -Force
cargo build --release
```

### 搜索结果为空但是确实有文件

- 检查 `.gitignore` 和默认跳过目录
- 检查 `glob` 是否只匹配文件名
- 检查 `limit` 和 `offset`
- 检查时间预算是否太小

### 中文乱码

- 用 `fs_stat detail=full` 查看实际编码判定
- 极短 GBK 文件可能被启发式判为 UTF-8
- `E_ENCODING_LOSS` 表示新内容无法用原编码表示

## 9. 升级与卸载

### 升级

首选自带命令，在**当前二进制所在位置**就地升级（查最新 Release → 下载 → SHA-256 校验 → 替换）：

```powershell
fsops upgrade --check   # 只查有没有新版
fsops upgrade           # 升级到最新版
fsops upgrade --force   # 已是新版也重装
```

- 只升级**当前命令对应的二进制**：用安装目录里的 `fsops` 就升级安装副本，用仓库 `target` 里的就升级仓库产物；其它副本需各自升级。
- 升级保留旧文件为 `fsops.exe.old-<时间戳>`（运行中的进程仍占用），下次 `fsops upgrade` 自动清理。
- 网络下载需要 `curl.exe`（Windows 10 1803+ 自带）。

升级后需让宿主重载：MCP 宿主执行 `/reload-mcp` 或重启，Hermes 执行 `hermes gateway restart`。**顺序是先升级二进制、再重载宿主**——只重载不会替换安装目录里的旧二进制。

也可重跑一行安装脚本（额外处理 PATH 与宿主注册；会停止 fsops 子进程后重试替换）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/install.ps1')).TrimStart([char]0xFEFF)))"
```

### 卸载

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ([scriptblock]::Create([Text.Encoding]::UTF8.GetString((New-Object Net.WebClient).DownloadData('https://github.com/tokenis2023/agent-ops/releases/latest/download/uninstall.ps1')).TrimStart([char]0xFEFF)))"
```

脚本会停止 fsops 子进程、删除默认安装目录、清理用户 `PATH`，并提示各宿主的移除命令。

自定义安装目录需要显式确认：

```powershell
.\scripts\uninstall.ps1 -InstallDir "$env:USERPROFILE\fsops-custom" -Force
```

卸载不会删除项目文件，也不会自动修改宿主 MCP 配置。fsops 不创建磁盘缓存、数据库或常驻服务；`fs_exec` 的后台任务随会话结束。
